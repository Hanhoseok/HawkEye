# 행동 라벨링 — 무엇을, 왜, 어떻게

> **지금 이것이 병목이다.** TAKE 후보를 8건 뽑아도 몇 건이 진짜인지 알 수 없다.
> 포즈를 붙여도 "후보가 줄었다"까지만 말할 수 있고 **"정확해졌다"는 말할 수 없다.**
> 라벨이 생기는 순간부터 모든 개선을 숫자로 비교할 수 있다.

---

## 1. 라벨에는 두 종류가 있다 — 섞지 말 것

| | **평가용** (지금 필요) | 학습용 (아직 아님) |
|---|---|---|
| 목적 | 정확도를 재기 위해 | 모델을 학습시키기 위해 |
| 양 | 2~3분 분량, 수십 건 | 수천 클립 |
| 비용 | 반나절 | 수 주 |
| 필요 시점 | **어떤 구조를 택하든 지금** | Action Recognition 모델을 만들기로 확정한 뒤 |

이 문서는 **평가용**을 다룬다.

---

## 2. 무엇을 찍는가

| 라벨 | 정의 |
|---|---|
| **TAKE** | 손이 상품에 닿아 상품이 선반에서 사람 쪽으로 옮겨진 구간 |
| **RETURN** | 들고 있던 상품을 선반에 되돌려 놓은 구간 |
| **BROWSE** | **선반 앞에 있었지만 상품을 집지 않은 구간** |

### BROWSE 를 반드시 함께 찍어야 하는 이유

TAKE 만 찍으면 **재현율은 재도 정밀도는 못 잰다.**
"후보로 잡혔는데 정답이 없다"가 진짜 오탐인지, 라벨을 빠뜨린 것인지 구분할 수 없기 때문이다.

BROWSE 가 있으면 오탐을 두 종류로 나눌 수 있다.

- **구경 오인** — 구경만 하는 사람을 집는 걸로 판정 → 우리가 풀려는 바로 그 문제
- **기타** — 선반 근처도 아닌데 잡힘 → 다른 종류의 버그

현재 baseline 이 막힌 지점이 정확히 "구경과 집기를 구분 못 함"이므로,
**이 구분이 없으면 개선 여부를 판단할 수 없다.**

### 구간의 시작과 끝

- 시작: 손이 상품 쪽으로 움직이기 시작한 프레임
- 끝: 상품을 들고 손이 선반을 벗어난 프레임
- 애매하면 **넉넉하게** 잡는다. 평가 시 '구간이 겹치는가'로 판정하므로 몇 프레임 오차는 무해하다.

### 판단이 어려울 때

- 상품을 집었는지 화면으로 확신할 수 없다 → **찍지 않는다.** 애매한 정답은 평가를 망친다.
- 여러 번 집었다 놨다 한다 → 각각 따로 찍는다.
- 두 사람이 겹쳐 누가 집었는지 모르겠다 → 찍지 않는다.

## 3. 어떻게 찍는가

```bash
python scripts/label_actions.py data/videos/store-aisle-detection.mp4 \
    --identities outputs/take-base/identities.jsonl \
    --out labels/store-aisle.csv
```

`--identities` 를 주면 화면에 `person_id` 박스가 함께 표시된다.
**라벨의 person_id 는 이 박스의 번호와 같아야 한다** — 평가기가 person 단위로 대조하기 때문이다.

| 키 | 동작 |
|---|---|
| `SPACE` | 재생 / 일시정지 |
| `→` `←` | 1 프레임 / `.` `,` 10 프레임 / `]` `[` 100 프레임 |
| `0~9` | 라벨링할 person 선택 / `TAB` 순환 |
| `t` `r` `b` | TAKE / RETURN / BROWSE 구간 시작·끝 (두 번 눌러 닫는다) |
| `x` | 진행 중인 구간 취소 / `u` 마지막 구간 삭제 |
| `s` | 저장 / `q` 저장하고 종료 |

하단 진행 바에 이미 찍은 구간이 색으로 표시되고, 중간에 껐다 켜도 이어서 작업할 수 있다.

### 출력 형식

```csv
person_id,action,start_frame,end_frame,start_sec,end_sec
2,TAKE,2480,2600,41.4,43.4
3,BROWSE,1400,1700,23.4,28.4
```

## 4. 찍고 나면 — 처음으로 정확도를 잴 수 있다

```bash
# 현재 설정 평가
python scripts/eval_takes.py labels/store-aisle.csv --takes outputs/take-base/take_candidates.jsonl

# 임계값을 스윕하며 최적점 찾기 (재추론 없이 초 단위)
python scripts/eval_takes.py labels/store-aisle.csv \
    --identities outputs/take-base/identities.jsonl --fps 59.9 --sweep
```

출력 예:

```
  속도    체류    후보   TP   FP   FN     정밀도     재현율     F1
  0.05   3.0     8    ?    ?    ?       ?       ?      ?
```

**판정 규칙**

| | 조건 |
|---|---|
| TP | 후보가 같은 person 의 TAKE 라벨과 프레임 구간이 겹친다 (라벨 하나당 후보 하나) |
| FP | 겹치는 TAKE 라벨이 없다. BROWSE 와 겹치면 '구경 오인'으로 따로 센다 |
| FN | 후보가 붙지 않은 TAKE 라벨 |

### 주의 — 같은 데이터로 고른 임계값

스윕으로 찾은 최적값은 **그 영상에 맞춘 값**이다.
다른 영상에서도 되는지는 별도로 확인해야 한다.
가능하면 라벨을 두 구간으로 나눠 한쪽으로 고르고 다른 쪽으로 검증한다.

## 5. 얼마나 찍어야 하나

**최소**: TAKE 10건 + BROWSE 10건. 이 정도면 정밀도/재현율의 대략적인 크기는 보인다.
**권장**: TAKE 25건 + BROWSE 25건. 임계값 스윕 결과를 신뢰할 수 있는 수준.

store-aisle 전체가 65초이고 사람이 6명이므로, 이 영상 하나로는 부족할 수 있다.
그때는 `people-detection.mp4` 나 추가 영상을 함께 라벨링한다.
