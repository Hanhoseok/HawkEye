## 2. 수집 시나리오

라벨링·평가에 쓸 시나리오. **정상/절도/혼동**을 균형 있게 확보한다. (혼동 = 오탐 테스트용)

| 유형 | 시나리오 | 기대 결과 |
|---|---|---|
| 정상 | 취득 → 결제 → 퇴장 | 알림 없음 |
| 정상 | 취득 → 일부 결제 → 나머지 반환 → 퇴장 | 알림 없음 |
| 절도 | 취득 → 미결제 → 퇴장 | HIGH_RISK |
| 절도 | 일부만 결제 → 미결제 반출 | HIGH_RISK |
| 혼동 | 취득 → 반환 → 퇴장 | 알림 없음 |
| 혼동 | 지갑/휴대폰 꺼내는 동작 | 알림 없음 |
| 혼동 | 가방에 넣고 결제 후 퇴장 | 알림 없음 |
| 복합 | 다중 인원 동시 존재 | 각자 정확 판정 |

체크리스트:
- [ ] 각 유형별 최소 N개 확보 (N = TODO)
- [ ] test 세트에 혼동 시나리오 반드시 포함

## 4. 라벨 포맷 (YOLO)

이미지 1장당 동일 이름의 `.txt`. 한 줄 = 한 객체:
```
<class_id> <x_center> <y_center> <width> <height>
```
- 좌표는 이미지 크기로 **정규화** (0~1)
- 소수점 6자리 권장
- 예:
```
0 0.500 0.620 0.180 0.540
1 0.512 0.334 0.121 0.208
```
- 객체 없는 이미지: 빈 `.txt` (배경 학습용)

### 라벨링 가이드
- bbox는 객체를 **꽉 차게**(여백 최소)
- 가림 객체: 보이는 부분 기준, 50% 이상 가려지면 TODO(포함/제외 규칙 확정)
- 잘린 객체(프레임 경계): 보이는 부분만
- 일관성: 같은 상품은 항상 같은 클래스로

## 6. POS 로그 데이터

시뮬레이션 또는 실측 결제 로그.
- 각 결제 레코드: `timestamp`, 결제 상품·수량
- 영상 timestamp와 **동일 시간 기준**으로 동기화
- 평가용으로 정상/절도 시나리오에 맞춰 결제 유무를 설계

예 (요약):
```json
{ "timestamp": "2026-09-18T14:03:21.5Z", "items": [{"product_class":"음료","quantity":1}] }
```

## 7. 데이터 분할

| 분할 | 비율(안) | 용도 |
|---|---|---|
| train | 70% | 학습 |
| val | 15% | 튜닝·검증 |
| test | 15% | 최종 평가 |

규칙:
- 같은 영상의 인접 프레임이 train/test에 섞이지 않게 **영상 단위**로 분할(누수 방지)
- test에는 혼동 시나리오 포함
- 분할 목록은 `data/splits/`에 파일로 고정(재현성)

## 10. 폴더 구조
```
data/
  raw/            # 원본 영상
  frames/         # 추출 프레임 (이미지)
  labels/         # YOLO 라벨 txt (frames와 짝)
  splits/         # train.txt / val.txt / test.txt
  pos_logs/       # POS 결제 로그 (JSON)
  zones/          # 매장별 zones.json
  classes.txt     # 클래스 id↔이름 매핑
```
