# 분석 도구 (workbench)

저장된 기록을 원본 영상 위에 그려, **프로그램이 무엇을 어떻게 판단했는지를 질문별로** 보는 도구다.
그때그때 만들던 확인용 페이지(오판 장면 보기, 구역 편집, 결제 라벨 도구)를 하나로 모으는 자리이고, 갤러리, 한 쌍 분석, 수치 조정, 정답 적기, 새 영상 추가까지 있다.

```bash
cd experiments/tracking
python workbench/server.py          # http://127.0.0.1:8770/  (내 컴퓨터에서만 열림)
```

처음 열면 기록(`outputs/dual_eval_pose3/`)을 읽어 보기 데이터를 만든다 — 38쌍에 1분 남짓, 그 뒤로는 바뀐 짝만 다시 만든다.
이미 처리한 영상은 다시 돌리지 않는다. 영상을 처리하는 것은 갤러리의 '새 영상 추가'(아래)나 `python scripts/dual_eval.py run`.

## 화면

**갤러리** — 여기서 시작한다. 영상마다 카드 한 장: 결과(절도를 잡음 / 놓침 / 정상 통과 / 정상인데 경보 / 판정 없음)와 한 줄 이유.
위쪽 숫자는 `dual_eval.py judge` 의 채점과 같다(맞은 영상, 판정이 실제로 나와서 맞은 것, 판정 없음, 손님 수). '틀린 것'·'판정 없음'으로 걸러 본다.

**한 쌍 분석** — 카드를 누르면 두 영상이 시차를 맞춰 함께 재생된다. 질문 하나를 고르면 영상 위 표시·타임라인·요약이 그 질문에 맞게 바뀐다.

| 질문 | 영상 위 | 타임라인 | 정답과 비교 |
|---|---|---|---|
| 사람 추적 | 손님 상자(번호마다 색)·추적 번호·발 점, 손님이 아닌 것으로 거른 신원은 회색 점선 | 신원마다 보인 구간, 새 신원·합침 | 손님 수 |
| 두 화면 같은 사람 | 두 화면에서 같은 색 = 같은 사람으로 이음, 짝 점수 | 선반 카메라 사람마다 누구와 이어졌나 | 정답 없음 — 눈으로 확인 |
| 물건 집기 | 칸·손목·프로그램이 본 물건, 손이 닿은 칸 강조 | 손 접촉 / 선반 가림·비교 / 칸 그림 변화 / 선반 앞 머묾 / 행동 판정 | 개수 정답 없음 — 절도 영상인데 0개면 표시 |
| 결제·판정 | 구역(계산대·출구·문 밖·선반 앞), 손님별 물건·결제 수와 판정 | 결제 / 출구 경고 / 최종 판정 | 정답표의 expected |

- 처음 열릴 때는 틀린 질문(빨간 점)이 먼저 선택된다.
- 오른쪽 요약의 `▶ 5.0초`, 시간 순서 기록, 타임라인의 구간·표식을 누르면 그 장면으로 간다.
- 키보드: 스페이스 재생·멈춤, ←→ 한 장면(1/15초), Shift+←→ 1초, 1~4 질문 바꾸기.
- 점 색: 초록 = 정답과 맞음, 빨강 = 틀림, 노랑 = 확인할 것 있음, 회색 = 정답이 없어 눈으로 봐야 함.
  **정답이 없는 것에는 맞음·틀림을 붙이지 않는다.**

**수치 조정** — 위쪽 '수치 조정'. 판정 값을 바꿔 저장된 기록으로 다시 판정하고(몇 초), 전후를 비교한 뒤 적용한다. 큰 규칙은 그대로 두고 기준값만 바꾼다.

- 바꿀 수 있는 값 16개: 결제(계산대에 서 있어야 하는 시간 …), 나감과 경보, 손님으로 세는 조건, 두 화면 같은 사람, 선반 사건의 주인.
  탐지·추적·신원·칸 그림 기준처럼 **영상을 다시 돌려야 반영되는 값은 여기 없다.** 구역은 아직 예전 구역 편집 페이지.
- 순서: **① 정상(N) 영상으로 확인**(몇 번이든) → **② 절도·복합 채점 열기** → **③ 적용**.
- **잠금**: 절도·복합 결과는 '채점 열기'를 눌러야 보이고, 연 것은 `labels/store01_dual/tune_log.jsonl` 에 남는다(값·전후 점수·달라진 영상).
  채점용 영상을 보며 값을 고치면 그 영상에만 맞는 값이 되기 때문이다 (한계 A-15). 연 횟수가 화면에 보인다. 이 기록 파일은 커밋해 둔다.
- 달라진 영상을 누르면 **초안 값으로 다시 판정한 장면**이 한 쌍 분석 화면에서 열린다 (위에 노란 띠).
- 적용하면 `configs/store01_dual_judge.yaml` 에 적히고, `scripts/dual_eval.py`·`run_tracking.py --dual-config`·갤러리가 그 값을 쓴다.
  되돌리려면 값을 원래대로 놓고 다시 적용한다 (코드 기본과 같아지면 파일에서 빠지고, 다 빠지면 파일이 없어진다).
- 한 쌍 분석의 요약에 붙은 **'이 기준 바꿔 보기'** 를 누르면 그 사실을 좌우하는 값으로 바로 간다.

**정답 적기** — 한 쌍 분석 화면의 다섯 번째 탭(키 5). 영상을 그 순간에 멈추고 버튼(또는 키)을 누른 뒤 화면에서 사람을 누른다.

| 적는 것 | 키 | 어떻게 | 채점되는 것 |
|---|---|---|---|
| 집음·놓음 | T · R | 집은(놓은) 사람을 전체 카메라에서 누름. 개수·칸은 목록에서 고침 | 손님마다 가져간 개수(집음 − 놓음)가 프로그램과 같은가 → '물건 집기' |
| 경보가 나야 하는 사람 | A | 물건을 들고 나간 사람을 전체 카메라에서 한 번 누름 | 경보가 그 사람에게 났는가 → '결제·판정' (한계 A-14) |
| 두 화면 같은 사람 | L | 선반 카메라에서 사람, 이어서 전체 카메라에서 같은 사람 | 그 시각 프로그램의 짝이 같은 사람인가 → '두 화면 같은 사람' |
| 결제 | P | 지금 시각에 결제 한 줄. 품목 수·결과는 목록에서 고침 | (판정에 쓰는 것은 `dual_eval.py judge --payments`) |

- **'누가'는 화면 위의 점으로 저장한다** — 프로그램의 손님 번호가 아니다. 정답이 프로그램의 판단에 기대지 않게 하려는 것이고,
  채점할 때 그 시각(앞뒤 0.7초) 그 점을 품은 가장 작은 사람 상자로 프로그램의 손님을 찾는다. 목록에 '프로그램: 손님 1'처럼 참고로 보인다.
- **집음·놓음은 '빠짐없이 적었음'을 체크해야 개수를 채점한다.** 아무도 안 집은 영상도 정답이므로, 비워 둔 채 체크하면 '0개'가 정답이 된다.
- 바꿀 때마다 저장되고(1초 안팎), 서버가 그 짝만 다시 채점해 다른 탭의 점·요약과 갤러리가 바로 바뀐다.
- 저장되는 곳: `labels/store01_dual/events/<짝>.json` (항목 하나가 한 줄 — **커밋한다**), 결제는 예전 결제 라벨 도구와 같은 `labels/store01_dual/payments.csv`.
- 갤러리에 '사람이 적은 정답' 칸(적은 영상 수, 집은 개수·두 화면 짝·경보 대상 점수)과 '정답 적은 것' 거르기가 생긴다.

**새 영상 추가** — 갤러리의 첫 카드. 두 각도 영상(전체 카메라·선반 카메라)을 고르고 세트(정상·절도·복합)·손님 수·경보 여부를 적으면, 올린 뒤 뒤에서 처리해 카드로 올린다.

- **같은 매장·같은 카메라 위치에서 찍은 영상만.** 구역(`zones/store01_dual`)·바닥 보정·띠 축을 그대로 쓴다. 카메라가 움직였거나 다른 매장이면 구역부터 다시 잡아야 한다 — 이 도구는 그것을 해 주지 않는다.
  받을 때 확인하는 것: 영상이 열리나, 16:9 인가, 두 영상 길이가 5초 넘게 다르지 않나, 5분 이하인가. 초당 장면 수가 기존(전체 60·선반 30)과 다르면 알려 준다.
- 이름은 세트 글자(N·T·C) + 번호 — 그대로 두면 다음 번호(N13, T11, C22 …)가 붙는다. 기존 도구들이 첫 글자로 세트를 읽어 이 규칙을 지킨다.
- 처리는 `scripts/dual_eval.py run --only <이름>` 을 따로 띄운다. CPU 로 영상 길이의 8~10배(20초 영상이면 약 3분), 한 번에 하나씩. 그동안 다른 화면은 그대로 쓸 수 있다.
  서버를 껐다 켜면 처리가 멈춘다 — 카드의 '처리 시작'을 누르면 이어서 한다. 실패하면 `outputs/workbench/jobs/<이름>.log`.
- **두 영상의 시차는 자동 추정이다** (두 화면의 손님 위치로, 믿기 어려우면 기존 영상들의 중앙값). 카드에 '시차 확인'이 붙는다 —
  영상을 열어 정답 적기 탭의 '두 영상의 시차'에서 같은 순간이 두 화면에 함께 보이게 맞추고 저장한다 (기존 영상의 시차도 여기서 고칠 수 있다).
- 생기는 것: 영상 `source/added/<이름>_angle1.*`·`_angle0.*` (저장소에 올리지 않음), 정답표 `truth.csv` 에 한 줄, `labels/store01_dual/added.csv` 에 한 줄, `sync.csv` 에 한 줄, 기록 `outputs/dual_eval_pose3/<이름>/`.
- 갤러리는 '2차 촬영'과 '추가한 영상'을 묶음으로 나눠 보여 주고 위쪽 숫자도 묶음별이다. `dual_eval.py judge` 는 추가한 영상도 함께 채점하므로, 2차 촬영만 보려면 `--only "N1,N2,…"` 처럼 고른다.
- **지우는 기능은 없다.** 잘못 넣었으면 위에 적은 다섯 곳(영상 두 개, 표 세 줄, 기록 폴더)을 손으로 지운다.

## 구성

| 파일 | 하는 일 |
|---|---|
| `server.py` | 서버. 영상 구간 이동·같은 컴퓨터 요청만 받기는 `scripts/review_serve.py` 의 것을 그대로 쓴다. 구역 편집 페이지의 요청도 받는다 |
| `data.py` | 기록 → 보기 데이터 (`outputs/workbench/`). `scripts/review_export.py` 의 `pair_data`(기록을 다시 판정하며 상자·신원·짝·선반 사건을 모음)를 쓴다. 장면 그림(카드용)도 여기서 |
| `analyze.py` | 보기 데이터 → 질문별 요약·타임라인 줄·기록. 영상·모델 라이브러리 없이 계산한다 (`tests/test_workbench_analyze.py`) |
| `labels.py` | 정답 적기 — 정답 파일 읽고 쓰기·값 확인 (`tests/test_workbench_labels.py`). 채점은 `analyze.py` 의 `score_labels` |
| `intake.py` | 새 영상 추가 — 파일 받기·영상 확인·정답표에 등록·처리 대기열·시차 추정과 저장 (`tests/test_workbench_intake.py`) |
| `tune.py` | 수치 조정 — 바꿀 수 있는 값 목록(`KNOBS`), 초안 판정(`outputs/workbench/drafts/`), 잠금과 기록, 적용 (`tests/test_workbench_tune.py`) |
| `static/` | 화면 (설치·빌드 없이 도는 HTML·CSS·JS) |

판정은 `scripts/dual_eval.py` 의 것 그대로다 — 이 도구가 따로 판정하지 않는다. 결제는 지금 기본인 '계산대에 서 있으면 결제'.

## 아직 없는 것 (다음 단계)

1. ~~수치 바꿔 보기~~ — 2단계에서 만듦 (위 '수치 조정'). 구역을 이 화면에서 고치는 것은 남음.
2. ~~정답 적기~~ — 3단계에서 만듦 (위 '정답 적기'). **정답 자체는 아직 한 편도 적지 않았다** — 영상을 보고 적어야 점수가 붙는다.
3. ~~새 영상 추가~~ — 4단계에서 만듦 (위 '새 영상 추가'). 추가한 영상을 지우는 기능, 카메라가 움직였을 때 구역을 다시 잡는 기능은 없음.
4. 결제 라벨(`payments.csv`)로 판정한 결과 보기, 설정끼리 비교.

## 알아 둘 것

- 기준에 못 미친 칸 그림 변화율은 기록에 남지 않는다(`slot_changes.jsonl` 은 기준을 넘은 것만). 그래서 "7.3% 였는데 기준 8% 에 모자랐다" 같은 숫자는 아직 화면에 못 보인다 — 영상을 다시 돌릴 때 모든 비교를 남기게 해야 한다.
- 영상은 H.265 라 크롬 계열 브라우저에서 열어야 한다.
- 결과(`outputs/workbench/`)와 영상(`source/`)은 저장소에 올리지 않는다.
- 수치 조정에 값을 더하려면 `tune.py` 의 `KNOBS` 에 한 줄 — 판정 단계에서 쓰는 절(risk·fusion·zones)만 넣는다.
- 보기 데이터의 모양을 바꾸면 `data.py` 의 `VERSION` 을 올린다 (전부 다시 만들게 됨).
