# 카메라 2대 방향 — 논문 6편을 우리에게 어떻게 쓰나

팀원 공유용 (2026-11-03). 카메라를 2대(선반 높이 angle0 + 높은 구석 angle1)로 늘리고 실시간으로 돌리며, 나중에 선반 센서를 붙이는 방향을 정하려고 논문 6편을 처음부터 끝까지 읽었다.
이 문서는 **논문마다 무엇을 했고, 우리에게 무엇을 쓰고, 무엇을 안 쓰는지(그리고 왜)** 를 정리한다.
이 근거로 만든 새 구조는 `docs/multiview-design.md` 에 있다. 아래의 **M-번호**는 그 문서의 설계 포인트 번호다.

- 논문 PDF 는 저장소에 올리지 않는다 (아래 링크로 받는다).
- 숫자는 모두 논문 본문·표에 적힌 값이다. 우리 쪽 숫자는 `store-test.md`·`limitations.md`·이번 측정(설계 문서 §2)에서 가져왔다.

## P1. MMPTrack — 겹쳐 보는 카메라 여러 대 추적 벤치마크

Han et al., *MMPTRACK: Large-scale Densely Annotated Multi-camera Multiple People Tracking Benchmark*, arXiv:2111.15157 — https://arxiv.org/abs/2111.15157

### 무엇을 했나
- 실험실에 환경 5개(Retail·Lobby·Industry·Cafe·Office)를 꾸미고 Azure Kinect 23대(Retail 6대)로 15FPS, 총 576분을 찍었다. 프레임마다 상자와 신원이 붙어 있다 (Table 1·2).
- **자동 라벨링**: 깊이 카메라들을 보정해 점구름을 만들고, 위에서 내려다본 높이 지도에서 사람을 찾아 3D 로 추적한 뒤 각 RGB 카메라로 투영한다. 사람은 신원 바뀜과 허위 탐지만 고친다.
  손으로 하면 414~4000 사람·일이 걸릴 일을 **한 명이 5시간 안에** 고쳤고 비용은 **약 1/800** 이다. 품질은 IDF1 100, MOTA 99.9 (§3.5~3.6, Table 3).
- 카메라 보정: ArUco 마커를 바닥에 두고 "카메라-마커" 연결 그래프를 만들어 외부 변수를 한 번에 최적화한다 (§3.3, 식 1).
- 기준 추적기 두 개를 평가했다 (Table 4·5).
  - **DMCT**: 카메라마다 '발 위치' 열지도 → 호모그래피로 바닥에 투영 → 위치마다 최댓값으로 합침 → 바닥에서 사람 찾기·추적. 바닥 탐지기를 학습하면(DMCT-TD) IDF1 60.2 → 74.8.
  - **VoxelTrack(P4)**: 공개 데이터로 학습한 그대로 쓰면 IDF1 55.2.
- **환경 데이터의 힘** (Table 6·8)
  - Retail 환경 IDF1: 그 환경 데이터 없이 27.7 → 넣으면 45.7.
  - 재식별(ReID): MSMT 로 학습한 그대로 Retail mAP 28.5 → 이 데이터로 미세조정 33.3. 14명만으로 처음부터 학습해도 31.6 으로 공개 모델보다 낫다.
- **Retail 이 다섯 환경 중 가장 어렵다.** 추적 IDF1 과 재식별 모두 꼴찌이고, 원인은 어수선한 배경이다 (§4.3.2).
- 평가는 바닥에서 반경 **1m** 기준 (§4.1).

### 우리에게 쓰는 것
| 가져올 것 | 어떻게 쓰나 | 설계 포인트 |
|---|---|---|
| DMCT 의 **후기 융합**(카메라별 발 위치 → 호모그래피 → 바닥에서 합침) | angle1 은 바닥(발)이 보인다(측정: 상자 아래가 화면 끝인 비율 6%). angle1 의 발 위치를 호모그래피로 매장 바닥 지도에 옮겨 계산대·출구·선반 앞 판단을 바닥 좌표로 한다 | M-3 |
| ArUco/마커 보정 | 매장 바닥에 종이 마커 4장 이상 → angle1 바닥 호모그래피. 바닥 타일 격자가 보여서 마커 없이 타일 모서리로도 가능 | M-3 |
| 환경 데이터로 다시 학습하면 크게 오름 (27.7→45.7, mAP 28.5→33.3) | 2단계 학습의 근거. 사람 탐지기(높은 시점), OSNet 재식별을 **우리 매장 영상으로 미세조정**한다. 지금 쓰는 OSNet 도 MSMT 로 학습한 것이다 | M-11 |
| Retail 이 가장 어렵다 (어수선한 배경) | 우리도 같은 문제를 이미 봤다: angle1 의자 위 외투를 사람으로 잡음(0.30~0.33), 비슷한 옷 4편 중 1편만 버팀(C-4) → 카메라별 '사람 아님 영역'과 교차 화면 확인이 필요 | M-2, M-4 |
| **자동 라벨링 = 센서로 정답 만들기** | 선반 무게 센서가 붙으면 "몇 시 몇 분, 3번 칸에서 1개 빠짐"이 자동으로 기록된다. 이것을 상품 모델·행동 모델의 학습 정답으로 쓰고 사람은 틀린 것만 고친다. 지금은 정답을 전부 눈으로 적는다(`labels/store01/truth_functions.md`, A-10·A-11) | M-8, M-11 |
| 바닥 1m 기준 평가 | 바닥 지도 위치 평가 기준으로 채택 | M-10 |

### 안 쓰는 것과 이유
- **깊이 카메라 자동 라벨링 장비**: 우리 매장에는 깊이 카메라가 없다. 대신 센서(무게)로 같은 생각을 한다.
- **MMPTrack 데이터로 학습·평가**: 실험실 매장(Retail 6대)이라 화각·조명이 우리와 다르다. 저자도 공개 데이터와 환경 차이를 문제로 꼽는다. 공개 범위·라이선스를 확인하기 전에는 계획에 넣지 않는다 (확인하면 교차 화면 연결 알고리즘의 사전 점검용으로만).

## P2. MVDet — 특징 지도를 바닥으로 투영하는 다중 카메라 탐지

Hou, Zheng, Gould, *Multiview Detection with Feature Perspective Transformation*, ECCV 2020 — https://github.com/hou-yz/MVDet

### 무엇을 했나
- 보정된 카메라 N대의 영상을 ResNet-18 로 특징 지도로 만든다. 카메라 보정값으로 **바닥 평면(z=0)으로 투영**(식 2, 3×3 행렬)해 이어 붙이고, 큰 커널 합성곱으로 주변을 함께 보며 바닥 점유 지도를 낸다.
- **무엇을 투영하나** (Fig. 5, Table 3, Wildtrack MODA)
  - 영상 픽셀: 26.8
  - 카메라별 탐지 결과(발 위치): 68.2
  - 특징 지도: **88.2**
  - 이웃 합성곱을 빼면 76.9
- 조건: Wildtrack 은 카메라 7대, 12×36m, 장면당 평균 **20명**, 한 지점을 평균 3.74대가 본다. 사람이 많아질수록(20→80명) 성능이 떨어진다 (Fig. 7).
- 학습: 입력 720×1280, 바닥 격자 10cm, RTX-2080Ti 2장. 판정: 점유 확률 0.4 이상, 0.5m 겹침 제거. 평가: 0.5m 안이면 정답.

### 우리에게 쓰는 것
| 가져올 것 | 어떻게 쓰나 | 설계 포인트 |
|---|---|---|
| 바닥 평면 투영 공식 (z=0 → 3×3 호모그래피) | angle1 발 위치 → 바닥 지도. 구역(계산대·출구·문 밖·선반 앞)을 화면 좌표가 아닌 **바닥 좌표**로 정의한다 (B-6 해결 방향) | M-3 |
| **탐지 결과만 투영해도 68.2** (단순 묶기는 11.3) | 우리처럼 카메라별 YOLO 결과를 바닥으로 옮겨 합치는 후기 융합도 쓸 만하다. 다만 **합치는 단계(연결 규칙)가 성능을 좌우한다** → M-4 에서 교차 화면 연결을 공들여 설계 | M-2, M-4 |
| 발이 보여야 바닥 투영이 맞다 (z=0 가정) | angle0 은 상자 아래가 화면 끝인 장면이 98%(N1)·77%(C3)다. 발 위치를 모르니 **angle0 의 사람은 바닥에 투영하지 않고** 선반 앞 띠 위의 좌우 위치로만 쓴다 | M-3 |
| 0.5m 평가 기준 | 바닥 위치 정확도 채점에 채택 | M-10 |

### 안 쓰는 것과 이유
- **바닥 탐지 신경망 그 자체** (지금 단계)
  - 보정이 맞는 카메라 여러 대가 같은 바닥을 겹쳐 봐야 한다. angle0 은 바닥을 거의 못 본다(위). 투영된 angle0 특징은 대부분 빈칸이거나 늘어진 그림자가 된다.
  - 이 방법이 이기는 상황은 **혼잡**(장면당 20~40명)이다. 우리 장면은 1~2명이고, 문제는 혼잡이 아니라 **비슷한 옷과 두 사람이 겹치는 것**(C-4, C03·C06 뒤바뀜)이다.
  - 학습에 바닥 위치 정답과 GPU 가 필요하다. 우리 개발 PC 는 GPU 를 못 쓴다(G-1).
- 카메라를 3대 이상 겹치게 다는 단계가 오면 2단계 선택지로 다시 본다 (설계 문서 §6).

## P3. EarlyBird — 바닥에서 바로 추적하는 초기 융합

Teepe et al., *EarlyBird: Early-Fusion for Multi-View Tracking in the Bird's Eye View*, WACV 2024 Workshops — https://github.com/tteepe/EarlyBird

### 무엇을 했나
- MVDet 구조에 ResNet-18 바닥 디코더와 **재식별(ReID) 특징 머리**를 붙였다. 바닥에서 사람 중심을 찾고, 그 자리의 외형 특징으로 시간 방향만 잇는다.
  카메라 사이 연결은 바닥 탐지 단계가 이미 풀어 준다.
- **연결 규칙** (§3.5)
  - 1단계: 거리 D = 0.98 × 외형 코사인거리 + 0.02 × 칼만 예측과의 마할라노비스 거리. 움직임이 말이 안 되면 무한대. 헝가리안 매칭, 기준 0.4.
  - 2단계: 남은 것끼리 **중심 거리 2.5m** 안이면 연결.
  - 연결 못 한 추적은 **10단계 동안 보관**했다가 다시 나타나면 잇는다.
- 결과 (Table 1~3): Wildtrack 탐지 MODA 91.2. 추적 IDF1 92.3 / MOTA 89.5 로, 같은 수준 탐지를 쓴 후기 융합 ReST(86.7 / 84.9)보다 +5.6 / +4.6.
  - 단계별 기여(IDF1): 기본 71.3 → 데이터 늘리기 84.5 → 디코더 91.1 → 화면 재식별 손실 92.3.
- **저자가 적은 한계** (§5)
  - 정확한 3D 정답과 카메라 보정이 필요하다.
  - **카메라가 동기화돼야 한다.** 시간이 어긋나면 같은 사람이 바닥의 다른 곳에 투영된다.
  - 모든 영상을 한 기계에서 동시에 처리해 메모리·연산이 크다.
  - 반대로 **후기 융합은 카메라별로 따로 처리하고 중앙에서 합칠 수 있고, 시간 어긋남에도 더 견딘다.**
  - 겹침이 적은 가장자리에서 정확도가 떨어진다 (Fig. 3).

### 우리에게 쓰는 것
| 가져올 것 | 어떻게 쓰나 | 설계 포인트 |
|---|---|---|
| **초기 융합의 전제 조건 목록** (동기화·3D 보정·큰 GPU) | 우리 상황을 하나씩 대 보면 **후기 융합이 맞다**. 두 영상은 30/60FPS 로 다르고 시작 시각도 다르다(측정 §2-3). 보정이 없고(B-6), GPU 도 없다(G-1). 저자가 말한 후기 융합의 장점(카메라별 따로 처리, 어긋남에 강함)이 그대로 필요하다 | M-2, M-9 |
| 2단계 연결 (외형 + 위치 → 남은 것은 거리로) | 매장 신원 연결에 그대로 옮긴다. 1단계 외형+바닥 위치, 2단계 바닥 거리. 다만 매장은 좁아서 2.5m 대신 **키 기준 거리**를 쓴다 (우리 기존 원칙: 속도·거리를 키로 나눔, `architecture.md` §3 ③) | M-4, M-5 |
| 잃은 추적을 잠시 보관했다가 잇기 | 우리 신원 계층의 '30초 보관'과 같은 생각이다. 카메라가 둘이면 한쪽에서 사라져도 다른 쪽에서 보이는 동안은 **잃은 것이 아니다**(C-16 상황 개선) | M-5 |
| 가장자리·겹침 적은 곳은 부정확 | 두 카메라가 함께 보는 곳(선반 앞)과 한 대만 보는 곳(문 근처는 angle1, 선반 위 물건은 angle0)을 나눠 **어느 판단을 어느 카메라가 하는지** 고정한다 | M-1 |

### 안 쓰는 것과 이유
- **초기 융합 신경망**: 위 전제 조건을 하나도 못 맞춘다. 3대 이상 + 동기화 + GPU 서버가 갖춰지는 단계에서 다시 본다.

## P4. VoxelTrack — 3D 격자에서 자세를 찾고 추적

Zhang et al., *VoxelTrack: Multi-Person 3D Human Pose Estimation and Tracking in the Wild*, arXiv:2108.02452 — https://arxiv.org/abs/2108.02452

### 무엇을 했나
- 카메라마다 관절 열지도와 재식별 특징을 만든다. **2D 에서는 결정하지 않고** 열지도를 3D 격자(10×10×4m, 62.5mm 칸)로 역투영해 평균을 낸 뒤, 3D 신경망으로 관절 위치를 찾는다.
  저자 말로 "어려운 결정은 모두 3D 에서 모든 화면을 합친 뒤".
- **가림을 아는 외형 합치기** (§4.1~4.2): 3D 자세와 카메라 위치로 카메라마다 누가 누구를 가리는지 계산한다. **70% 넘게 가려진 화면의 외형은 가중치 0** 으로 뺀다.
- 연결 근거 비교 (Panoptic, Table 4)
  - 3D 위치만: IDF1 93.8, 신원 바뀜 90번
  - 외형만(가림 무시): 94.4, 15번
  - 외형 + 가림 처리: **98.7, 0번**
- 카메라 수 (Table 3): 5대→3대로 줄이면 관절 오차 18.5 → 24.9mm, IDF1 98.7 → 93.1. "관절이 **두 화면 이상**에서 보이면 대체로 정확하다".
- 3D 부분은 **카메라 보정값만으로 만든 합성 열지도로 학습**할 수 있다. 저자는 "소매점 같은 새 환경에 바로 적용 가능"이라고 적었다 (§6.1).
- 속도: 가벼운 판(MobileNetV2)은 카메라 5대 입력에 2080Ti 1장으로 15FPS.

### 우리에게 쓰는 것
| 가져올 것 | 어떻게 쓰나 | 설계 포인트 |
|---|---|---|
| **가려진 화면의 외형은 빼고 합치기** (가림 70% 초과 → 0) | 두 사람이 겹치면 angle0 은 뒤에 선 사람이 거의 안 보인다(C03 그림: 검은 상의 두 사람의 뒷모습이 겹침). 사람 상자가 다른 사람 상자에 70% 넘게 덮이면 그 화면의 외형은 신원 비교에서 뺀다. 우리 기존 '가장자리 사진은 비교하지 않음'(C-8)과 같은 원칙을 가림에도 넓히는 것이다 | M-4 |
| 외형 + 위치를 함께 써야 신원 바뀜이 사라진다 | 매장 신원 점수 = 바닥 위치 + (가림 처리한) 외형. 어느 하나만 쓰지 않는다 | M-4 |
| "판단은 합친 뒤에" | 카메라별 층(①②③)은 '관찰'만 내고, 집음·결제·절도 판단은 합친 뒤(⑤⑥)에서만 한다. 우리 기존 원칙(판단 층은 영상을 모름, `test_contract.py`)을 카메라 2대로 넓힌다 | M-2 |
| 관절이 두 화면 이상에서 보여야 3D 가 정확 | 우리 두 카메라가 함께 보는 공간은 **선반 앞**뿐이다. 3D 손목 위치는 2단계에서 선반 앞 구역에 한해 계산한다 (Skarimva 와 함께) | M-6 |
| 3D 부분은 보정값만으로 합성 학습 | 2단계 3D 손목 위치를 학습형으로 바꿀 때, 우리 매장 정답 없이 보정값만으로 학습하는 길이 있다는 근거 | M-11 |

### 안 쓰는 것과 이유
- **3D 격자 자세 추정 신경망 전체**: 2대가 함께 보는 곳이 선반 앞뿐이다. 매장 전체를 격자로 만들면 angle1 한 대만 보는 칸이 대부분이다. 논문은 5대→3대만 줄여도 정확도가 떨어졌고(위 표), 2대는 실험하지 않았다. GPU 도 필요하다(G-1).

## P5. Skarimva — 골격 행동 인식은 다중 카메라 응용이다

Bermuth, Poeppel, Reif, *Skarimva: Skeleton-based Action Recognition is a Multi-view Application*, arXiv:2602.23231 (v2 2026-05) — https://arxiv.org/abs/2602.23231

### 무엇을 했나
- NTU-RGBD 의 카메라 3대 영상을 보정·동기화 정보 없이 다시 맞추고(부록 A), 여러 화면으로 **삼각측량한 3D 골격**을 새로 만들었다(RapidPoseTriangulation, RTX4080 에서 약 130FPS, 카메라 배치마다 재학습 불필요).
  그것을 기존 행동 인식 모델(MSG3D·DG-STGCN·ProtoGCN)에 넣었다.
- 결과 (Table I·III): 모델 구조를 안 바꿔도 **오류가 절반 넘게 준다.** 예: MSG3D 90.8 → 96.5 (NTU-60). 최고 97.5 / 95.4.
- 손가락·얼굴 점을 다 넣으면 오히려 떨어질 수 있다. 몸 + 손끝 몇 개가 가장 좋다(wb25·wb31).
- **실용 메모** (§V, 부록)
  - **대충 한 보정과 동기화 없음**으로도 이득을 봤다. 보정은 체스판을 휴대폰 화면에 띄워 할 수 있다.
  - 실시간 창 방식(행동 시작·끝을 모르고 고정 길이로 자름): 3초 95.7 / 2초 94.7 / 1초 92.8 (DG-STGCN).
  - 새 행동을 **예시 5개**로 배우기: 84.9 (NTU-120).
  - 모델은 2~4.5M 파라미터, 140~189FPS (RTX4080).
- 저자가 적은 한계: 골격만으로는 **물체가 걸린 행동**을 헷갈린다(물 마시기 vs 간식 먹기). 물체 상자도 삼각측량해 함께 넣으라고 제안한다 (부록 D).

### 우리에게 쓰는 것
| 가져올 것 | 어떻게 쓰나 | 설계 포인트 |
|---|---|---|
| 여러 화면 골격이 행동 인식 입력 품질을 올린다 | 손 뻗기 판단의 입력을 angle0 의 가까운 관절로 바꾼다. 지금은 비스듬한 카메라에서 '몸 상자가 선반에 머묾'(dwell)만 쓰고, 그래서 구경과 집기를 못 가른다(D-1, C 17편 중 11편 거짓 경보). angle0 은 사람이 크게 보여(키 중앙 986px) 손목이 또렷하다 | M-6 |
| **대충 보정·동기화 없이도 이득** | 1단계는 3D 없이 angle0 의 2D 손목만 쓰고, 2단계 3D 삼각측량도 **정밀 보정 장비 없이**(체스판·바닥 타일) 시작할 수 있다는 근거 | M-6, M-9 |
| 실시간 창 1~3초 정확도 | 행동 인식을 실시간으로 돌릴 때 창 길이를 2초부터 시험한다. 우리 손 뻗기는 1~2.5초짜리 짧은 집기를 놓쳤다(store-test 3차, 21/25) | M-6 |
| 5개 예시로 새 행동 배우기 | 집음/놓음/만짐을 우리 영상 몇 개로 학습하는 2단계 계획의 근거. 우리는 N·T 영상 수십 편뿐이다 | M-11 |
| **골격만으로는 물체 행동을 헷갈린다 → 물체도 같이** | 우리 실험과 같은 결론이다: RetailAction 에서 관절만으로는 집음/놓음 AUC 0.60, 손 사진을 더하면 0.71(D-16). 그래서 손 뻗기(관절) + 선반 지도(물체)를 합치는 지금 구조를 유지하고, 손목이 **어느 물건 칸에 닿았는지**로 둘을 칸 단위로 묶는다 | M-6, M-7 |

### 안 쓰는 것과 이유
- **NTU 결과 숫자를 매장에 기대하는 것**: 실험실에서 정면으로 찍은 전신 행동(발차기 등)이다. 매장 선반 앞 손동작과 다르다.
- 지금 단계의 GCN 행동 모델 학습: GPU 와 행동 정답이 필요하다 → 2단계 (M-11).

## P6. Complementary-View MHT — 위 화면 + 수평 화면으로 같은 사람 잇기

Han et al., *Complementary-View Multiple Human Tracking*, AAAI 2020 — https://github.com/HanRuize/CVMHT

### 무엇을 했나
- **위에서 본 화면**(드론, 전체 동선은 잘 보이지만 사람은 머리와 어깨뿐)과 **수평 화면**(머리에 단 GoPro, 외형은 잘 보이지만 자주 가림)을 동시에 찍었다.
  두 화면 각각 추적하면서 **두 화면의 같은 사람을 프레임마다 잇는다.**
- 방법 (§3)
  - 두 영상을 같은 길이(예: 10프레임) 조각으로 나눈다. 조각 안에서 상자 겹침 50% 이상이면 이어 짧은 추적 조각(tracklet)을 만들고, 3프레임 미만은 버린다.
  - 인접 조각·두 화면의 조각 4묶음을 정수계획으로 한 번에 잇는다. 못 찾은 사람은 '빈 노드'로 처리한다(가림·화면 밖).
  - 연결 점수
    - 화면 사이: **위치 관계**(사람들의 공간 배치를 맞춤)와 외형(평균 사진 Siamese)을 w1 으로 섞는다 (w1=0.3).
    - 같은 화면 안: 색 히스토그램과 등속 운동을 w2 로 섞는다 (w2=0.5).
- 결과 (Table 1·2·3)
  - 화면 사이 같은 사람 맞히기: CVIDF1 **84.0**, CVMA 78.3. 각 화면을 따로 추적한 뒤 잇는 방식은 44.7 / 43.2.
  - 수평 화면 추적 IDF1 72.2 (최고 단일 추적기 58.1). **위 화면의 도움으로 수평 화면의 가림·화면 밖 문제를 되찾는다** (Fig. 6: 가려졌다 나타나도, 화면 밖에 나갔다 돌아와도 원래 번호).
  - 위 화면 IDF1 80.2 > 수평 72.2. 가림이 위 화면에서 드물기 때문이다.
  - **화면 사이 위치 근거를 빼면 CVIDF1 84.0 → 15.5, 외형을 빼면 82.6.** 화면 사이 연결은 위치가 결정적이고 외형은 보조다.
  - 섞는 비율(w1·w2·c0)에 결과가 민감하지 않다 (Table 4).
- 위 화면용 YOLOv3 를 **위에서 본 사람 사진 600장**으로 미세조정했다. 두 영상은 손으로 시간을 맞췄다. 속도는 Matlab CPU 1.74FPS.

### 우리에게 쓰는 것
| 가져올 것 | 어떻게 쓰나 | 설계 포인트 |
|---|---|---|
| **역할이 다른 두 화면** (전체 동선 화면 + 가까운 외형 화면) | 우리 두 카메라가 정확히 이렇다. angle1 은 높은 구석에서 매장 전체·바닥·문을 보고, angle0 은 선반 높이에서 손·물건·상반신을 본다. **매장 신원과 동선은 angle1, 손·물건은 angle0** 이 맡는다 | M-1, M-5 |
| 위 화면은 가림이 적어 추적이 낫다 (80.2 vs 72.2) | C03 에서 angle0 은 두 사람의 뒷모습이 겹쳐 보이고, angle1 은 둘이 나란히 보이며 바지·신발 색이 다르다. 신원의 기준을 angle1 에 둔다 | M-5 |
| **화면 사이 연결은 위치가 결정적** (위치 빼면 15.5) | 우리 상황에서는 외형이 더 약하다. 두 사람이 같은 검은 상의, 흰 티 2명 4편 중 1편만 버팀(C-4), 신원 확인 기준이 아슬아슬함(E-4). 그래서 angle0↔angle1 연결의 1순위는 **위치 관계**다: "angle0 선반 앞 띠에서 왼쪽에 선 사람 = angle1 바닥 지도에서 선반 앞 그 자리의 사람" | M-4 |
| 짧은 조각 단위로 잇기 + 빈 노드 | 프레임마다 결정하지 않고 0.5초 조각 단위로 잇는다. 한쪽 화면에만 있는 사람(angle0 화면 밖, 문 근처)은 '짝 없음'을 허용한다 | M-4 |
| 다른 화면의 번호로 되찾기 | angle0 에서 가려졌다 나타나거나 화면 밖에 나갔다 들어와도, angle1 이 그동안 계속 본 사람이면 **같은 매장 신원**을 유지한다. 재입장 4건 중 2건만 이어 붙인 문제(C-6·C-18)를 angle1 이 문을 보는 것으로 줄인다 | M-5 |
| 교차 화면 평가 지표 CVIDF1·CVMA (식 9·10) | 두 카메라의 같은 사람 맞히기를 채점하는 지표로 채택 | M-10 |
| 위 시점용 탐지기를 600장으로 미세조정 | 높은 시점 사람 탐지가 나빠지는 문제(B-4)의 해결 경로. angle1 사람 사진을 2단계에 수백 장 라벨링해 미세조정 | M-11 |
| 손으로 시간 맞춤 | 우리 두 영상도 시간을 맞춰야 한다(측정 §2-3). 촬영 때 박수·시계 화면, 소프트웨어 보정 도구 | M-9 |

### 안 쓰는 것과 이유
- **정수계획 풀이기(CPLEX)와 4묶음 동시 최적화**: 사람이 1~2명인 매장에서는 헝가리안 매칭 두 번(화면 사이, 시간 방향)으로 충분하다. 실시간과 설치 부담을 생각해 단순한 쪽을 고른다.
- 드론(완전 수직) 가정: angle1 은 완전 수직이 아니라 비스듬히 내려다본다. 그래서 사람이 머리만 보이지 않고 몸 전체가 보여(키 중앙 621px) 외형 비교도 어느 정도 쓸 수 있다. 위치 1순위·외형 보조라는 결론은 유지하고, 섞는 비율은 우리 N 영상으로 정한다.
