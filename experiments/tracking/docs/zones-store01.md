# 구역 — 코드에서 하는 일 (store01 카메라 2대)

구역 파일: `zones/store01_dual/floor.yaml`(전체 카메라 angle1), `zones/store01_dual/angle0.yaml`(선반 카메라).
고치는 곳: 구역 편집 페이지 `scripts/zone_editor.html` (`python scripts/review_serve.py` 로 열기). 2026-11-08 정리.

## 구역은 두 가지 좌표로 적는다

| 좌표 | 어디 | 판단 방법 |
|---|---|---|
| **바닥 cm** | 전체 카메라 바닥 구역 5개 | 사람의 발 점(기본 발목, 아래)을 바닥 지도(호모그래피)로 cm 로 옮겨, 그 점이 다각형 안인지 (`FloorZoneMap`). 겹침 비율은 없다 — 안이면 1.0 |
| **화면 비율 0~1** | 사람 아님 영역, 전체 카메라 선반 영역, 선반 카메라 선반 상자·칸 | 화면 위 상자·다각형 그대로 |

바닥 지도는 화면 4점 ↔ 바닥 4점(통로 120×240cm **가정**, 실측 아님)으로 만든다. cm 값 자체는 믿을 수 없고 모양·위치만 맞다.

발 점은 `zones.foot_point` 로 고른다: `ankle`(카메라 2대 기본, 2026-11-09 — 관절 모델의 발목, 없으면 상자) 또는 `bbox`(상자 아래 가운데, 11-08 까지의 기본·카메라 1대 기본).
발목을 쓰려면 전체 카메라도 관절 모델(yolo-pose)이어야 해서 `configs/store01_dual.yaml`·`dual_eval.py` 기본이 함께 바뀌었다. 두 카메라 짝의 띠 위치는 여전히 상자 아래 가운데.
상자 아래 가운데는 팔을 뻗거나 다리가 가려지면 실제 발에서 수십 px 벗어난다 — **구역을 실제 바닥 자리에 꼭 맞게 그리면 발목과 함께 써야 한다** (B-15).
지금 적용본 구역은 상자 발 점의 분포로 그린 것이라 상자와 짝이다.

## 바꾸면 어떻게 확인하나

- **판정 다시 돌리기로 확인 (18초)**: 바닥 구역 5개, 선반 앞 띠, 보정점, band_map. 기록(추적 결과)은 그대로 두고 판정만 다시 한다.
- **영상을 다시 돌려야 반영 (`dual_eval.py run`)**: 사람 아님 영역, 선반 카메라 선반 상자·칸, 전체 카메라 '선반 앞 머묾' 손 뻗기 후보. 탐지·추적 단계에서 쓰여 기록에 이미 들어가 있다.

## 전체 카메라 바닥 구역

| 구역 (종류) | 하는 일 | 쓰는 코드 |
|---|---|---|
| **shelf** (SHELF) | ① 손님 조건: 발이 shelf·counter·aisle 에 1초 이상 = 손님 ② '선반 앞 한 명': 여기 선 사람을 적어 두고, 선반 카메라 사건(손 접촉·방문)의 주인을 짝으로 못 정하면 그때 여기 한 명뿐인 사람 ③ 결제 취소: 계산대에서 결제된 뒤 다시 여기 오면 취소 ④ (영상 다시) 발이 3초 이상 천천히 머물면 집기 동작 후보 | `risk.inside_zones`, `fusion.shelf_zone` → `shelf_events._band_owner`, `customers.dwell_payments`, `interaction/detector.py` |
| **counter** (CHECKOUT) | ① 손님 조건 ② 발이 1.5초 이상 = 그때까지 가진 것을 모두 결제 (결제 기록 없는 매장) | `risk.payment_mode: dwell`, `dwell_pay_seconds` |
| **door** (EXIT) | ① 0.5초 이상 = 출구에 다가섬 → 이대로 나가면 HIGH_RISK 인 손님에게 WARNING ② 여기서(마지막 2초 안) 사라져 3초 안 돌아오지 않으면 최종 판정 ③ 영상 끝: 여기서 화면 끝에 걸친 사람만 나간 것으로 ④ 문턱에서는 신원 확인 값을 재지 않음 | `risk/engine.py` 5)·6-b)·`finish` |
| **outside** (OUTSIDE) | ① 매장 안에 있던 사람의 발이 0.5초 이상 = '문 밖으로 나감' 최종 판정 ② 나간 사람이 여기 아닌 곳에서 다시 보이면 판정 되돌림 | `risk/engine.py` 6-a), `customers.observe` |
| **aisle** (OTHER) | 손님 조건만 (매장 안 바닥) | `risk.inside_zones` |

- 이름이 설정과 묶여 있다: `shelf`·`counter`·`aisle` (`configs/store01_dual.yaml` `risk.inside_zones`), `shelf` (`fusion.shelf_zone`). 이름을 바꾸면 설정도 바꿔야 한다.
- 종류가 묶여 있다: CHECKOUT = 결제, EXIT = 출구, OUTSIDE = 나감. 같은 종류 구역이 둘이면 둘 다 같은 일을 한다.
- 구역끼리 겹쳐도 된다 (aisle 이 shelf·counter 를 품음) — 한 점이 여러 구역에 동시에 들어간다.

## 전체 카메라 그 밖

| 이름 | 하는 일 |
|---|---|
| **band** (선반 앞 띠, 바닥 y 0~169cm) | 두 카메라 사람 잇기의 공통 좌표. 전체 카메라 발의 바닥 y 를 0~1 로 바꿔 선반 카메라 사람 위치와 비교 (-0.3~1.3 밖이면 '위치 없음' → 짝 안 맺음). 바꾸면 `dual_eval.py calibrate` 로 band_map 도 다시 |
| **calibration** (보정점) | 바닥 지도 행렬. 모든 바닥 구역·띠의 바탕. 바꾸면 cm 로 적힌 구역이 화면에서 따라 움직이고 band_map 도 다시 맞춰야 함 |
| **ignore_image** (사람 아님 영역 3개) | (영상 다시) 전체 카메라 탐지에서 이 상자와 IoU 0.5 이상인 사람 상자를 버린다 — 의자 위 외투, 오른쪽 아래 외투, 관절 모델이 외투 일대를 잡는 오른쪽 전체 높이 큰 상자 `[0.71, 0, 1, 1]` (B-11, 3번째는 11-09). 탐지 모델을 바꾸면 그 모델 상자에 맞춰 다시 볼 것 |
| **shelf_image** (전체 카메라 선반 영역) | 지금 안 씀: 전체 카메라 팔 뻗기(`fusion.overview_reach_seconds`, 기본 0)를 켜면 손목이 이 안 0.3초 = 팔 뻗기, 발이 이 안인 사람은 가짜 사람으로 뺌 |

## 선반 카메라 (angle0.yaml)

| 이름 | 하는 일 |
|---|---|
| **shelves.shelf** (선반 영역) | (영상 다시) 사람 상자가 겹치면 '가림'. 가림이 끝나면 앞뒤 물건 탐지를 비교해 선반 방문 하나(사라짐·생김). 물건 탐지는 가운데가 이 영역 안인 물건만. 처음엔 사각형(`box`)만 됐고, 2026-11-08 부터 `polygon` 을 주면 다각형으로 판단(`box` 는 그 둘레로 같이 저장) |
| **card·bottle·box** (칸, SHELF) | (영상 다시) ① 손목이 칸 안 0.3초 = 손-칸 접촉(집기 동작) ② 사람이 비킨 뒤 칸 그림이 바뀌었나 ③ 센서 칸 이름 대응. **사각형만** — 칸 그림 비교가 사각형으로 잘라 비교한다 |
| **band_map** | 선반 카메라 사람 상자 가운데 x → 띠 위치 (띠 = a·x + b). 그리는 값이 아니라 `dual_eval.py calibrate` 가 정상(N) 영상으로 맞춘다 |
