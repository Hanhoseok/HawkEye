# 시나리오 영상 촬영 가이드

목적: **"경보가 실제 상황에서 얼마나 맞게 울리는가"를 수치로 재기 위한 영상**을 직접 찍는다.
공개 데이터에는 출구·계산대·결제가 함께 있는 영상이 없어서, 지금은 로직이 도는지만 확인한 상태다
(`docs/risk-pipeline.md` §6).

영상 파일만으로는 부족하다. **"영상 속에서 실제로 무슨 일이 있었는지" 적은 기록**이 함께 있어야
시스템의 판정과 비교할 수 있다. 이 문서는 그 두 가지를 어떻게 준비하는지 정리한다.

---

## 1. 찍기 전에 정할 것

### 카메라 각도 — 가장 먼저

실제 무인매장에 설치할 각도로 찍는다. **각도에 따라 시스템이 쓰는 단서가 정반대**이기 때문이다
(비스듬하면 손의 높이, 천장에서 수직이면 손과 선반 사이 거리 — `docs/merl-evaluation.md` §6).
다른 각도로 찍은 영상으로 잰 수치는 실제 설치 환경에서의 성능이 아니다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| 천장 모서리에서 비스듬히 (일반 CCTV) | 사람 전신과 옷이 잘 보여 신원 유지가 쉽다 | 사람끼리·선반에 가려지기 쉽다 |
| 천장에서 수직으로 | 가려짐이 적다. MERL 로 검증한 설정을 그대로 쓸 수 있다 | 머리·어깨만 보여 신원 유지가 약하다 |

### 한 화면에 들어와야 하는 것

카메라는 1대다. 아래 셋이 **모두 한 화면**에 들어와야 한다.

- **선반** (물건을 집는 곳)
- **계산대** (결제하는 곳) — 서 있는 자리가 보이도록
- **출구** — **선반과 확실히 떨어진 문 바로 앞.** 선반 근처와 겹치면 구경하는 손님에게 경보가 울린다(`docs/risk-pipeline.md` §5에서 실제로 겪음)
- **가능하면 문 밖이 조금 보이게** (유리문이면 좋다). 문 밖에서 보이는 것이 '나갔다'는 가장 확실한 증거다
  (`docs/risk-pipeline.md` §5-A). 문 밖이 안 보이면 '출구 쪽에서 사라져 3초'로 판단하는데, 문 앞이 붐비면 가려진 것과 헷갈린다

### 사람 크기

**화면 안에서 가장 멀리 있을 때도 사람 키가 화면 세로의 1/5 이상**이어야 한다.
그보다 작으면 사람을 놓치기 시작한다(`docs/scale-limits.md`: 모델 입력 기준 키 65픽셀).
카메라를 너무 높거나 멀리 두지 않는다.

### 촬영 설정

- 스마트폰으로 충분하다. 1080p 또는 720p, 30fps.
- **삼각대 등으로 고정한다.** 카메라가 움직이면 구역 좌표가 전부 어긋난다.
- 촬영 중 줌·각도를 바꾸지 않는다. 바꿔야 하면 파일을 나눈다.

## 2. 찍을 장면

각 장면을 **3~5번씩**, 가능하면 **사람과 옷차림을 바꿔 가며** 찍는다.
한 사람이 한 번만 찍으면 그 사람 옷에 맞춘 결과인지 알 수 없다.

| 번호 | 장면 | 기대 판정 | 확인하는 것 |
|---|---|---|---|
| S1 | 집고 → 계산 → 나감 | CLEAR | 결제 연결 |
| S2 | 집고 → 그냥 나감 | **HIGH_RISK** | 기본 경보 |
| S3 | 구경만 하고 나감 | CLEAR | 구경을 집기로 오인하지 않는가 |
| S4 | 2개 집고 1개만 계산 → 나감 | REVIEW | 일부 결제 |
| S5 | 집었다 되돌려놓고 → 나감 | CLEAR | **지금은 HIGH_RISK 가 날 것**(되돌려놓기 미구현). 오경보를 재기 위한 장면 |
| S6 | 두 명 동시: A 는 계산, B 는 그냥 나감 | A CLEAR / B HIGH_RISK | 두 사람의 기록이 섞이지 않는가 |
| S7 | 계산대에 두 명이 줄 서서 차례로 계산 | 둘 다 CLEAR | 결제를 맞는 사람에게 연결하는가 |
| S8 | 집고 → 선반 뒤로 잠깐 가려졌다 나옴 → 그냥 나감 | HIGH_RISK | 가려져도 같은 손님으로 이어지는가 |

S1·S2·S3 가 가장 중요하다. 시간이 부족하면 이 셋부터 찍는다.

**결제**는 실제 결제가 아니어도 된다. 계산대에서 결제하는 동작을 하고, 그 시각과 개수를 기록하면 된다.

## 3. 함께 적어야 하는 기록 — 정답표

영상마다 **실제로 일어난 일**을 적는다. 이것이 없으면 시스템이 맞았는지 판단할 수 없다.
촬영하면서 적어도 되고, 찍은 뒤 영상을 보며 적어도 된다.

| 영상 | 사람 | 옷 특징 | 집은 시각(초) | 되돌려놓은 시각 | 결제 시각 · 개수 | 나간 시각 | 기대 판정 |
|---|---|---|---|---|---|---|---|
| s2_take1.mp4 | A | 검은 후드 | 12 | - | - | 25 | HIGH_RISK |
| s1_take1.mp4 | B | 흰 셔츠 | 8 | - | 20 · 1개 | 31 | CLEAR |

- 시각은 **영상 재생 시각(초)** 으로 적는다. 동영상 플레이어에 보이는 시간 그대로면 된다.
- "옷 특징"은 시스템이 매긴 손님 번호와 실제 사람을 맞추는 데 쓴다.
- 결제 칸은 그대로 결제 기록 파일(`payments.csv`)이 된다.

## 4. 찍은 뒤 — 영상이 쓰이는 과정

"찍고 올리면 끝"은 아니지만, 사람이 해야 할 일은 **영상 파일과 정답표를 넘겨주는 것**까지다.
나머지는 이렇게 진행한다.

1. **영상 넣기** — `data/videos/` 에 둔다. **GitHub 에는 올리지 않는다**(용량, 그리고 찍힌 사람의 얼굴이 담긴다).
   팀원과 나눌 때는 구글 드라이브 같은 곳을 쓴다.
2. **구역 좌표 잡기** — 영상의 한 장면에 격자를 입혀 저장하고, 선반·계산대·출구의 꼭짓점 좌표를 읽어
   `zones_<매장이름>.yaml` 을 만든다. 카메라를 고정했다면 한 번만 하면 된다.
   ```bash
   python scripts/export_frame.py data/videos/s1_take1.mp4 --frame 100
   ```
3. **결제 기록 만들기** — 정답표의 결제 칸을 `payments.csv` 로 옮긴다. `person_id` 는 비워 둔다
   (실제 POS 처럼 계산대 위치로 손님을 찾게 한다).
4. **실행** — 영상마다 전체 파이프라인을 돌린다.
   ```bash
   python run_tracking.py --source data/videos/s1_take1.mp4 --zones zones_store.yaml \
       --payments payments_s1_take1.csv --out-dir outputs/scenario/s1_take1
   ```
   결과: 판정 기록, 결제 연결 기록, 경보 장면 이미지, 빨간 박스가 그려진 결과 영상.
5. **채점** — 판정 기록과 정답표를 비교해 장면별로 맞은 비율을 낸다.
   HIGH_RISK 를 놓친 경우(경보 누락)와 CLEAR 여야 할 손님에게 경보가 난 경우(오경보)를 따로 센다.
   채점 스크립트는 영상이 생기면 정답표 형식에 맞춰 작성한다.
6. **원인 찾기** — 틀린 경우마다 어느 단계에서 틀렸는지 본다: 사람을 놓쳤나 / 신원이 섞였나 /
   집기를 놓쳤나 / 결제를 다른 사람에게 연결했나 / 출구 구역이 잘못 잡혔나.
   이 구분이 되어야 다음에 무엇을 고칠지 정할 수 있다.

---

## 5. 개인정보

- 찍히는 사람에게 **촬영 목적을 알리고 동의**를 받는다.
- 실제 매장에서 찍는다면 매장의 허락을 받고, 다른 손님이 찍히지 않게 한다.
- 영상은 저장소에 올리지 않는다(`.gitignore` 가 `data/videos/*`, `*.mp4` 등을 막고 있다).
