# 검증 영상 촬영 설계 — 지금까지 만든 것을 한 번의 촬영으로 재현·채점하기

> 2026-10-07 개편. 처음 판(출구·계산대 장면 S1~S8)에 선반 물건·집음/놓음 장면을 합치고,
> 그동안 찾은 한계(`docs/limitations.md`)에서 나온 촬영 조건을 넣었다. 처음 판의 장면은 아래 표에 번호를 바꿔 모두 남겼다.

## 0. 왜 찍나 — 공개 영상으로 못 채운 것

공개 영상 149편을 훑었지만(`docs/validation-set.md`) **물건이 하나씩 보이는 선반 + 사람 + 계산대 + 출구 + 정답**이
함께 있는 영상은 없었다. 그래서 지금은 기능마다 다른 영상으로 '돌아가는지'만 확인한 상태다.
이 촬영 하나로 아래 기능을 **같은 영상, 같은 정답표**로 채점한다.

| 기능 | 지금까지 확인 | 이 촬영으로 확인할 것 | 관련 한계 |
|---|---|---|---|
| 사람 추적·신원 유지 | MERL·UCF (정답 없이 눈으로) | 번호가 끊기거나 섞이는 횟수 | C-4, C-6, C-16 |
| 집기 감지 (손 뻗기) | MERL F1 0.73 | 손 뻗은 순간을 놓치거나 헛잡는 횟수 | D-1~D-3 |
| 선반 물건 식별 → 사라진 자리 | Pexels 3편 (1개씩) | 2개 이상, 같은 종류 중 몇 번째, 다른 자리에 놓기 | A-6, A-11, D-11 |
| 집음 / 놓음 / 만짐 판정 | Pexels 집음만, 나머지는 테스트만 | 놓음·만지기만·자리 바뀜 | D-6, D-15 |
| 손님별 물건 수 | Pexels | 사람별 최종 개수 | D-5 |
| 결제 연결 | 테스트만 | 계산대에서 맞는 사람에게 붙는가 | A-1, A-2 |
| 출구 판정 (WARNING → HIGH_RISK / REVIEW / CLEAR) | UCF 039·047 | **결제하고 나가는 손님이 통과되는가** | A-1, A-3, E-8 |

## 1. 세트 — 작은 매장 하나를 만든다

강의실이나 동아리방에 **선반 1개, 계산대 1개, 출구 1개**를 둔다. 위에서 본 배치:

```
            ┌──────────────────────────────────────────┐
            │  [선반] ■ ■ ■ ■ ■   (2단, 폭 약 1m)        │
            │                                          │
            │         ← 통로 (사람이 오가는 곳) →        │
            │                                          │
            │  [계산대]                       [출구 문] │──▶ 문 밖 (조금 보이게)
            │                                          │
            │                      📷 카메라 (선반 맞은편 위) │
            └──────────────────────────────────────────┘
```

- **출구는 선반에서 2~3m 이상 떨어지게.** 선반 앞에서 구경하는 자리가 출구 구역에 걸리면 구경하던 손님에게 판정이 난다
  (store-aisle 에서 실제로 겪음, E-7).
- **문 밖이 조금 보이게** (열린 문, 유리문). 문 밖에서 보이는 것이 '나갔다'의 가장 확실한 증거다(E-6).
  안 보이면 '출구 쪽에서 사라져 3초'로 판단하는데, 붐비면 가려진 것과 헷갈린다(E-2).
- 입구와 출구를 **다른 문**으로 할 수 있으면 좋다. 같은 문이면 들어올 때마다 CLEAR 판정이 하나씩 나온다(E-8, 틀리진 않음).
- 계산대는 사람이 **서서 계산하는 자리**가 화면에 보이게. 그 자리에 서 있는 사람에게 결제가 붙는다.

## 2. 카메라 — 한 대로 사람과 선반 물건을 함께

우리 시스템은 **카메라 한 대 화면에서** 선반 물건과 사람을 함께 봐야 '누가 가져갔나'를 정한다. 그래서 각도와 거리가 가장 중요하다.

| 항목 | 기준 | 이유 |
|---|---|---|
| 위치 | 선반 **맞은편** 벽 위, 높이 2~2.5m, 아래로 30~45° 비스듬히 | 선반 **정면**의 물건과 사람 전신이 함께 보여야 한다. 천장에서 수직이면 선반 정면이 안 보인다(MERL·RetailAction 에서 상품이 안 잡힌 이유) |
| 화면에 들어올 것 | 선반 전체, 계산대 서는 자리, 출구 문 + 문 밖 조금 | 한 화면에서 모두 판정 |
| 해상도·속도 | 1920x1080, 초당 30장 (최소 15장) | |
| 영상 형식 | **H.264** | 한호석 님 확인: H.265 카메라는 대시보드 라이브가 안 나옴(PR #14) |
| 물건 크기 | 화면 속 물건 폭 **48px 이상** (1080p 기준) — 선반 폭 1m 가 화면 가로의 **1/4 이상** 차지하게 | 물건 탐지(1280 해상도)에서 32px 미만이면 하나씩 안 잡힌다(D-14) |
| 사람 크기 | 가장 먼 곳에서도 사람 키가 화면 세로의 1/5 이상 | 65px 미만이면 사람을 놓친다(B-3) |
| 고정 | 삼각대나 벽 고정. 촬영 중 줌·각도 변경 금지 (바꾸면 파일을 나눔) | 구역·선반 좌표가 어긋난다 |
| 조명 | 일정하게. 창 역광·반사 피하기 | 역광에서 같은 사람도 다르게 보였다(E-5) |

**물건 크기 계산 예**: 화면 가로가 실제 4m 를 담으면 1px ≈ 2mm 이므로 48px ≈ 10cm.
→ **폭 10cm 이상인 물건**을 쓰거나, 카메라를 선반에 더 가깝게 둔다.

한호석 님의 실제 카메라(VIGI)를 쓴다면: 지금 우리 프로그램은 실시간 주소(RTSP)를 바로 못 받으므로(F-5),
**녹화 파일**(카메라 녹화 또는 중계기에서 저장)로 받아 돌린다.

## 3. 진열 — 지금 모델이 알아볼 수 있게

지금 물건 탐지는 **일반 YOLO(일상 물체 80종)** 라서, 그 80종에 드는 물건이어야 하나씩 잡힌다. 상품 모델(2단계)이 생기기 전까지는 이 조건이 필수다.

- **쓸 물건**: 페트병·캔 음료(bottle), 컵·텀블러(cup), 사과·오렌지·바나나(apple/orange/banana), 책(book), 그릇(bowl), 곰인형(teddy bear)
- **배경과 색이 다른 물건**: 흰 벽 앞 흰 병은 사람 눈엔 보여도 하나도 안 잡혔다(Pexels 10566656)
- **한 줄로, 물건 폭의 절반 이상 띄워서.** 겹쳐 쌓거나 뒤에 숨기면 셀 수 없다(D-12)
- **2단**, 단마다 4~6개. **같은 종류 3개를 나란히** 한 묶음 포함 (같은 종류 중 몇 번째인지 — S-B5)
- 촬영마다 **같은 배치로 되돌린다.** 시작 전 선반 사진 한 장 (정답표의 '처음 배치')

## 4. 출연자

- 2~4명, **옷 색이 서로 다르게.** 장면 하나(S-D4)는 일부러 **비슷한 옷**(검은 상의 등)으로 — 잘못 합칠 위험(C-4)을 잰다.
- 같은 장면을 **사람을 바꿔 3번** 찍는다. 한 사람만 찍으면 그 사람 옷에 맞춘 결과인지 알 수 없다.
- 결제는 진짜일 필요 없다. 계산대에서 계산하는 동작을 하고 **시각과 개수**만 기록한다.

### 장면 사이에 찍을 것 (보정용, 1번만)

1. **빈 매장 10초** — 선반 지도 기준, 구역 좌표 잡기
2. **한 명이 구역마다 3초씩 서기**: 선반 앞 → 계산대 → 출구 → 문 밖 — 구역이 맞게 그려졌는지 확인
3. **가장 먼 곳에 서 있기 5초** — 사람 크기 확인

## 6. 정답표 — 영상과 함께 반드시

정답표가 없으면 채점할 수 없다. **세 장**을 만든다(엑셀이나 구글 시트, CSV 로 저장).

**① 사람표** `people.csv`

| 영상 | 사람 | 옷 특징 | 들어온 시각(초) | 나간 시각(초) | 기대 판정 |
|---|---|---|---|---|---|
| sB2_1_A.mp4 | A | 빨간 후드 | 2.0 | 31.5 | HIGH_RISK |

**② 행동표** `events.csv` — 선반에서 한 일마다 한 줄

| 영상 | 시각(초) | 사람 | 행동 | 단 | 몇 번째 | 물건 | 개수 |
|---|---|---|---|---|---|---|---|
| sB2_1_A.mp4 | 12.4 | A | 집음 | 1 | 2 | 페트병 | 2 |
| sB3_1_B.mp4 | 9.0 | B | 집음 | 2 | 1 | 사과 | 1 |
| sB3_1_B.mp4 | 15.2 | B | 놓음 | 2 | 1 | 사과 | 1 |

행동은 집음 / 놓음 / 자리 바뀜 / 만지기만 중 하나. 자리는 위에서 1단, 왼쪽부터 1번째(카메라 화면 기준).

**③ 결제표** `payments.csv` — 그대로 프로그램 입력이 된다

| time_sec | items | person_id |
|---|---|---|
| 20.5 | 1 | (비움) |

`person_id` 는 비워 둔다. 실제 POS 처럼 계산대 위치로 손님을 찾게 한다.

**기록하는 요령**
- 촬영자 말고 **기록 담당 1명**을 둔다. 시각은 나중에 영상을 보며 적어도 된다(재생 시각 그대로).
- 장면 시작마다 **장면 번호를 적은 종이를 카메라에 1초 보여 준다**(슬레이트). 파일을 헷갈리지 않는다.
- 파일 이름: `s<장면>_<반복>_<사람>.mp4` (예: `sB3_2_C.mp4`).

## 7. 촬영 당일 순서와 시간

| 순서 | 할 일 | 시간 |
|---|---|---|
| 1 | 세트 배치, 카메라 고정, 화면 확인 (위 2절 표로 점검) | 30분 |
| 2 | **시험 촬영 1분 → 노트북에서 바로 돌려 보기** (물건이 하나씩 잡히나, 사람 번호가 붙나) | 15분 |
| 3 | 보정용 장면 (5절 끝) | 5분 |
| 4 | ★★★ 장면 7개 × 3번 | 약 40분 |
| 5 | ★★ 장면 | 약 60분 |
| 6 | 정답표 확인 (빠진 시각 채우기) | 20분 |

- [ ] 선반 폭이 화면 가로의 1/4 이상이다 (물건 48px 이상)

- [ ] 출연자 옷 색이 서로 다르다 (S-D4 제외)
- [ ] 정답표 세 장 양식과 기록 담당이 있다
- [ ] 출연자 촬영 동의를 받았다

## 9. 찍은 뒤 — 영상이 쓰이는 과정

사람이 할 일은 **영상 파일과 정답표 세 장을 넘겨주는 것**까지다. 나머지는 이렇게 진행한다.

1. **영상 두기** — `data/videos/<촬영이름>/`. **GitHub 에는 올리지 않는다**(용량, 찍힌 사람 얼굴). 팀 공유는 구글 드라이브 등으로.
2. **구역·선반 좌표** — 보정용 빈 매장 장면에서 한 번만 잡는다.
   ```bash
   python scripts/export_frame.py data/videos/<촬영>/calib_empty.mp4 --frame 100
   ```
   → `zones_<촬영>.yaml` (선반 SHELF, 계산대 CHECKOUT, 출구 EXIT, 문 밖 OUTSIDE) + 선반 영역 `--shelf`
3. **실행** — 장면마다 전체 프로그램. 상황판으로 보면서 돌릴 수 있다.
   ```bash
   python run_tracking.py --source data/videos/<촬영>/sB3_1_B.mp4 --zones zones_<촬영>.yaml \
       --shelf "shelf1=x1,y1,x2,y2@<선반구역>" --payments payments_sB3_1_B.csv --show
   ```
   결과: 판정(`risk_events.jsonl`), 행동(`actions.jsonl`), 선반 방문(`shelf_visits.jsonl`), 결과 영상.
4. **채점** — 정답표와 결과를 비교하는 스크립트로 기능별 점수를 낸다(영상이 생기면 정답표 양식에 맞춰 작성):
   - 추적: 사람 수가 맞나, 번호가 끊기거나 섞인 횟수
   - 집기 감지: 손 뻗은 순간을 잡은 비율 / 헛잡은 횟수
   - 선반: 사라진 자리·개수가 맞은 비율, 누구에게 붙였나
   - 행동: 집음·놓음·만지기만이 맞은 비율
   - 판정: 경보 누락(HIGH_RISK 를 놓침)과 오경보(CLEAR 여야 할 손님에게 경보)를 따로
5. **원인 찾기** — 틀린 경우마다 어느 단계에서 틀렸나: 사람을 놓쳤나 / 신원이 섞였나 / 손 뻗기를 놓쳤나 /
   선반이 잘못 셌나 / 결제를 다른 사람에게 붙였나 / 구역이 잘못 잡혔나. 결과는 `limitations.md` 상태에 반영한다.

## 10. 개인정보

- 찍히는 사람에게 **촬영 목적을 알리고 동의**를 받는다.
- 실제 매장에서 찍는다면 매장 허락을 받고, 다른 손님이 찍히지 않게 한다.
- 영상은 저장소에 올리지 않는다(`.gitignore` 가 `data/videos/*` 를 막는다).
