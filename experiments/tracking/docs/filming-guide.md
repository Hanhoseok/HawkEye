# 검증 영상 촬영 설계 — 실제 무인매장에서

> 2026-10-07 개편: 실제 무인매장 한 곳에서 촬영 허락을 받았다. 세트를 만드는 대신 **실제 매장 구조·CCTV·결제기**를 쓰도록 다시 짰다.
> 이전 판(강의실 세트 촬영)은 git 기록에 있다. 장면은 그대로 '손님 카드'로 옮겼다.

## 한눈에 보는 흐름

| 단계 | 누가 | 무엇을 | 결과물 |
|---|---|---|---|
| **① 사전 답사** (30~60분, 1회) | 팀 2명 | 매장 구조·CCTV·결제기·선반 확인, 시험 촬영 1분 | 매장 지도, 카메라 자리, 시험 영상 |
| **② 준비** | 팀 | 시험 선반 정하기, 손님 카드·정답표 출력, 역할 나누기 | 카드 16장, 정답표 양식 |
| **③ 촬영 당일** (약 2시간) | 팀 4명 | 보정 장면 → 손님 카드 순서대로 촬영 | 우리 카메라 영상 + 정답표 |
| **④ 매장에서 받아 오기** | 팀 1명 | CCTV 녹화, 결제 기록 (촬영 시간대만) | 실제 설치 각도 영상, 결제 시각·개수 |
| **⑤ 실행·채점** | tracking | 장면마다 프로그램 실행, 정답표와 비교 | 기능별 점수, 한계 문서 갱신 |

실제 매장이라 세트보다 좋은 점이 셋이다.
- **CCTV 가 실제 설치 각도다** → "우리 카메라 각도를 모른다"(B-1)에 처음으로 답이 생긴다.
- **결제기가 진짜다** → 결제 기록(시각·개수)으로 "결제하고 나간 손님이 통과되나"(A-1, A-2)를 진짜로 잰다.
- **조명·진열·동선이 진짜다** → 공개 영상으로 못 채운 '우리 매장 같은 영상'(A-11)이 생긴다.

어려운 점도 셋이다.
- **진열이 빽빽하다** → 지금 물건 탐지(일반 YOLO)는 빽빽한 상품을 하나씩 못 잡는다(D-14). 그래서 **시험 선반 한 칸**만 우리 조건으로 바꿔 둔다(3절).
- **CCTV 가 선반 정면을 못 볼 수 있다** → 그래서 **우리 카메라를 한 대 더** 둔다(2절).
- **다른 손님이 있을 수 있다** → 영업 전·손님 적은 시간에 찍는다(7절).

## ① 사전 답사 — 이것만 확인해 오면 된다

| 확인할 것 | 왜 | 기록 |
|---|---|---|
| 매장 구조: 입구·출구(같은 문인가), 결제기 위치, 선반 배치 | 구역(선반·계산대·출구) 그리기, 동선 짜기 | 손으로 그린 평면도 + 사진 |
| **기존 CCTV**: 몇 대, 어디서 어느 방향, 화면에 무엇이 보이나 | 실제 설치 각도. 출구·결제기가 보이는 카메라가 있나 | 녹화기 화면 사진 |
| CCTV 녹화를 **파일로 내보낼 수 있나** (mp4, H.264, 해상도) | 지금 프로그램은 실시간 주소(RTSP)를 못 받는다(F-5) — 파일로 받는다 | 가능 여부, 방법 |
| **결제 기록**을 받을 수 있나 (거래 시각·품목 수, 촬영 시간대만) | 결제 연결 채점. 없으면 기록 담당이 영상을 보고 적는다 | 가능 여부, 형식 |
| **시험 선반 후보**: 앞이 트인 선반(유리문 냉장고 X), 우리 카메라를 맞은편에 세울 자리 | 선반 정면이 보여야 물건을 하나씩 센다 | 사진, 선반 폭 |
| 조명·창(역광), 콘센트, 삼각대 놓을 자리 | 역광에서 같은 사람도 다르게 보였다(E-5) | 메모 |
| 촬영 가능 시간 (영업 전/손님 적은 시간) | 다른 손님이 찍히지 않게 | 날짜·시간 |

**답사 때 시험 촬영 1분**: 시험 선반 앞에 우리 카메라를 세우고 1분 찍어 노트북에서 바로 돌린다.
```bash
python scripts/screen_videos.py <시험영상>.mp4 --out outputs/screening/store_test.csv
```
'선반물건 좋음'(물건 3개 이상, 32px 이상)과 사람 '좋음'이 나와야 한다. 안 나오면 카메라를 더 가깝게.

## ② 카메라 두 대

| | 📷 A. 매장 CCTV (그대로) | 📷 B. 우리 카메라 (스마트폰 + 삼각대) |
|---|---|---|
| 자리 | 이미 달린 그대로 | 시험 선반 **맞은편**, 높이 1.8~2.5m, 아래로 비스듬히 |
| 보는 것 | 매장 전체, 출구, 결제기 | 시험 선반 정면 + 사람 전신 (출구·결제기도 보이면 더 좋음) |
| 검증하는 기능 | 사람 추적, 결제 연결, 출구 판정 | 선반 물건, 집음·놓음, 손님별 개수 |
| 설정 | 매장 설정 그대로, 녹화 파일로 받음 | 1080p, 30fps, H.264, 고정 (줌·각도 변경 금지) |
| 물건 크기 | — | 화면 속 물건 폭 **48px 이상** = 선반 폭 1m 가 화면 가로의 1/4 이상 |

- B 한 대에 시험 선반 + 결제기 + 출구가 다 들어오면 **B 하나로 모든 기능**을 한 번에 돌릴 수 있다. 안 되면 기능별로 A·B 를 나눠 채점한다.
- 두 카메라를 맞추는 법: 장면 시작마다 **장면 번호 종이 + 박수 한 번**을 두 카메라에 보이게. 휴대폰 시계 화면을 B 에 1초 보여 주면 CCTV 시각과 맞출 수 있다.
- 두 카메라의 사람 번호를 서로 잇는 기능은 아직 없다(카메라 한 대 기준, B-6). 그래서 채점은 카메라별로 한다.

## ③ 시험 선반 — 한 칸만 우리 조건으로

매장 허락을 받아 **선반 한 칸(폭 약 1m, 2단)** 만 다시 진열한다. 끝나면 원래대로 되돌린다.

- **일반 YOLO 가 아는 물건**: 페트병·캔 음료(bottle)가 가장 좋다. 컵(cup), 과일(apple/orange/banana), 책(book)도 된다.
  상품 모델(2단계)이 생기기 전까지는 이 조건이 필수다.
- **폭 10cm 이상, 한 줄로, 물건 폭의 절반 이상 띄워서.** 겹치거나 뒤에 숨으면 셀 수 없다(D-12).
- **배경(선반·벽)과 색이 다른 것** — 흰 배경에 흰 병은 실패했다.
- 단마다 4~6개, **같은 음료 3개를 나란히** 한 묶음 포함.
- 처음 배치를 **사진으로 찍어 두고** 매 촬영 뒤 그대로 되돌린다(진열 담당).
- 정직한 손님 장면에서 집은 물건은 **실제로 결제**한다(그 결제가 결제 기록이 된다). 비용·환불은 매장과 미리 정한다.

## ④ 손님 카드 — 한 장 = 한 사람의 한 번 방문

출연자에게 카드 한 장씩 주고 그대로 움직이게 한다. **들어와서 나갈 때까지 한 번에** 찍는다.

### ★★★ 필수 7장 (사람 바꿔 3번씩)

| 카드 | 하는 일 | 기대 결과 | 확인하는 것 |
|---|---|---|---|
| 1 정직한 손님 | 1개 집기 → 결제기에서 결제 → 나감 | 물건 1 · 결제 1 → **CLEAR** | 통과가 맞게 되나 (A-1) |
| 2 그냥 나가는 손님 | 1개 집기 → 그대로 나감 | WARNING → **HIGH_RISK** | 기본 경보 |
| 3 구경만 하는 손님 | 선반 앞에서 보기만 → 나감 | 물건 0 → **CLEAR** | 구경을 집기로 오인 안 함 |
| 4 일부만 내는 손님 | **한 번에 2개** 집기 → 1개만 결제 → 나감 | 물건 2 · 결제 1 → **REVIEW** | 개수 세기 (D-5) |
| 5 마음 바꾼 손님 | 1개 집기 → **제자리에 되돌려놓기** → 나감 | 집음 → 놓음 · 물건 0 → **CLEAR** | 되돌려놓기 오경보 (D-6) |
| 6 숨기는 손님 | 1개 집어 **가방에 넣기** → 나감 | 집음 1 → **HIGH_RISK** | 숨겨도 선반 빈자리로 잡나 (D-13) |
| 7 두 사람 | A: 카드 1 / B: 카드 2 를 **동시에** | A CLEAR / B HIGH_RISK | 두 사람 기록이 안 섞임 |

### ★★ 권장 5장 (2번씩)

| 카드 | 하는 일 | 기대 결과 | 확인하는 것 |
|---|---|---|---|
| 8 자리 옮기는 손님 | 집어서 **다른 자리에** 놓기 → 나감 | 자리 바뀜 · 물건 0 | 자리 바뀜 판정 |
| 9 골라 집는 손님 | 같은 음료 3개 중 **가운데** 1개 → 결제 → 나감 | "1단 2번째" 집음 → CLEAR | 같은 종류를 자리로 구별 |
| 10 차례로 두 사람 | A 가 1개 집고 떠난 뒤 B 가 1개 | 사람별 1개 | 차례면 각자에게 |
| 11 동시에 두 사람 | 둘이 선반 앞에 함께, A 만 집음 | 지금은 '누구 것인지 못 정함' | 알려진 한계 재현 (D-11) |
| 12 망설이는 손님 | 집고 → 출구 앞에 섰다가 → 돌아와 결제 → 나감 | WARNING 만 → 최종 CLEAR | 경보 두 단계 |

## ⑥ 정답표 — 세 장

**① 사람표** — 카드 한 장에 한 줄

| 영상 | 카드 | 사람 | 옷 | 들어온 시각 | 나간 시각 | 기대 판정 |
|---|---|---|---|---|---|---|
| c05_1_A.mp4 | 5 | A | 빨간 후드 | 2.0 | 31.5 | CLEAR |

**② 행동표** — 선반에서 한 일마다 한 줄

| 영상 | 시각(초) | 사람 | 행동 | 단 | 몇 번째 | 물건 | 개수 |
|---|---|---|---|---|---|---|---|
| c05_1_A.mp4 | 9.0 | A | 집음 | 1 | 2 | 콜라 | 1 |
| c05_1_A.mp4 | 15.2 | A | 놓음 | 1 | 2 | 콜라 | 1 |

행동: 집음 / 놓음 / 자리 바뀜 / 만지기만. 자리: 위에서 1단, 카메라 B 화면 왼쪽부터 1번째.

**③ 결제표** — 그대로 프로그램 입력(`payments.csv`)

| time_sec | items | person_id |
|---|---|---|
| 20.5 | 1 | (비움) |

매장 결제 기록을 받으면 그 시각으로 채우고, 못 받으면 기록 담당이 영상 시각으로 적는다. `person_id` 는 비워 둔다(결제기 앞에 선 사람을 프로그램이 찾게).

파일 이름: `c<카드>_<반복>_<사람>.mp4` (예: `c05_2_B.mp4`). 정답표 시각은 **카메라 B 영상 재생 시각**.

## ⑦ 매장과 미리 정할 것 · 개인정보

- **촬영 시간**: 영업 전이나 손님 적은 시간. 촬영 중 **안내문**을 문에 붙인다.
- **다른 손님이 찍히면** 그 구간은 쓰지 않고 지운다.
- **CCTV 녹화·결제 기록**은 촬영 시간대만, 팀 내부 검증용으로만 받는다고 약속한다.
- 영상은 **저장소에 올리지 않는다**(`.gitignore`가 `data/videos/*` 를 막음). 매장 이름도 문서에 쓰지 않는다.
- 출연자 **촬영 동의**를 받는다.
- 시험 선반 재진열 허락, 결제한 물건 처리(구매·환불)를 미리 정한다.

## ⑧ 받아 온 뒤 — tracking 이 하는 일

1. 영상 두기: `data/videos/store/` (카메라 B), `data/videos/store_cctv/` (카메라 A)
2. 구역 그리기: 보정 장면에서 한 번 — 선반(SHELF), 결제기 앞(CHECKOUT), 출구(EXIT), 문 밖(OUTSIDE) + 시험 선반 영역(`--shelf`)
   ```bash
   python scripts/export_frame.py data/videos/store/calib_empty.mp4 --frame 100
   ```
3. 실행 — 상황판으로 보면서
   ```bash
   python run_tracking.py --source data/videos/store/c05_1_A.mp4 --zones zones_store.yaml \
       --shelf "shelf1=x1,y1,x2,y2@test_shelf" --payments payments_c05_1_A.csv --show
   ```
4. 채점 — 정답표와 결과(`risk_events.jsonl`, `actions.jsonl`, `shelf_visits.jsonl`)를 비교하는 스크립트(영상이 오면 정답표 양식에 맞춰 작성):
   추적(번호 끊김·섞임), 집기 감지(놓침·헛잡음), 선반(자리·개수·누구), 행동(집음·놓음), 판정(경보 누락·오경보)
5. 틀린 경우마다 원인 단계 찾기 → `limitations.md` 상태 갱신. CCTV 영상으로 **실제 설치 각도에서의 사람 크기·탐지**도 재서 B-1 을 갱신한다.
