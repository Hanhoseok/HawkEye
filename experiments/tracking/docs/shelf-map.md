# 선반 지도 — 어느 자리의 물건이 사라졌고, 그때 누가 있었나 (1단계)

## 목표

"집는 동작"을 세는 대신 **선반에서 물건이 몇 개, 어느 자리에서 줄었는지** 세어, 그때 선반 앞에 있던 손님에게 붙인다.

    손님 3 이 선반 앞에 섬 -> 손을 뻗음 -> 떠남
    선반 지도: 떠나기 전 [1단 1번째 병, 1단 2번째 스프레이, 1단 3번째 펌프병]
               떠난 뒤   [1단 1번째 병,                    1단 2번째 펌프병]
    -> "1단 2번째 스프레이가 사라짐 -> 손님 3"

이게 되면 지금의 약점 두 가지가 풀린다.
- 개수: 동작 수 ≠ 물건 수라서 REVIEW 를 따로 뒀다. 선반 개수를 세면 정확한 개수가 나온다.
- 되돌려놓기: 다시 놓으면 선반에 '생김'으로 나온다. 별도 감지가 필요 없다.

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| **1** | 선반 지도 + 전후 비교 + 손님에게 붙이기 (탐지는 일반 YOLO) | ✅ 이 문서 |
| **1-B** | 선반 확인 개수를 손님 기록(위험 판정)에 연결 | ✅ 아래 '손님 기록 연결' |
| 2 | 상품 탐지 모델 — 우리 상품으로 학습한 YOLO, 또는 SKU-110K 모델 + DINOv2 사진 비교 | 상품·진열 결정 필요 |
| 3 | 손님 장부를 "품목별 개수"로, POS 를 품목 단위로 대조 | |

## 동작 (`src/shelf/monitor.py`)

1. **선반 지도 확정** — 선반 앞에 아무도 없을 때 약 0.6~1초 동안 본 탐지를 모아,
   **대부분의 장면(60%)에서 보인 물건만** 확정한다(한두 장면만 튀는 오탐·누락 제거).
   높이로 단을 나누고 단 안에서 왼쪽부터 순서를 매긴다.
2. **가림** — 사람 상자가 선반 영역과 겹치면 그 장면으로는 세지 않고, 누가 가렸는지만 기록한다.
3. **비교** — 가림이 끝나면 새 지도를 만들어 **자리(위치)로 짝을 맞춘다**. 같은 종류가 여러 개여도 자리로 구별한다.
   종류 이름은 보조로만 쓴다(일반 YOLO 는 큰 통을 '변기'로 보는 등 이름이 자주 틀린다).
   짝이 없는 이전 물건 = 사라짐, 짝이 없는 새 물건 = 생김.
4. **확정** — 바뀐 상태가 관찰 시간만큼 더 유지돼야 확정한다. 손이 잠깐 가려 생긴 깜빡임을 거른다.
5. **손님에게 붙이기** — 가린 사람이 한 명이면 그 사람, 여럿이면 정하지 않는다, 아무도 안 보였으면 '모름'(손만 들어온 경우).

형식(`ShelfItem`, `ShelfChange`)은 실험 단계라 팀 공통 형식(`core/types.py`)에 넣지 않았다. 채택되면 팀에 공유한 뒤 옮긴다.

## 시험 영상

공개 데이터에서 맞는 영상을 찾지 못했다.
- RetailAction(천장 시점)은 일반 YOLO 로 선반 물건이 거의 안 잡혔다(60개 샘플 중 2개만 3개 이상).
- 매장 통로 영상(store-aisle)은 그릇이 수백 개 빽빽하게 쌓여 있어 29~40개만 잡혔다.

그래서 **고정 카메라로 선반 정면을 찍고 사람이 물건을 가져가는 무료 스톡 영상**(Pexels)을 썼다.
영상은 저장소에 올리지 않는다.

| 영상 (Pexels ID) | 장면 |
|---|---|
| 10566654 (11.5초) | 선반 위 병 4개를 가까이서 찍음. 팔이 들어와 두 번째 스프레이를 가져감 |
| 10566665 (19.8초) | 넓은 화면, 남성이 선반 앞에 와서 앞쪽 세탁 세제 병을 가져감 |

## 결과

| 영상 | 정답 | 결과 |
|---|---|---|
| 10566654 | 두 번째 자리 스프레이를 가져감 (팔만 보임) | ✅ **1단 2번째 사라짐**. 주인은 '정하지 못함' — 화면 가장자리로 들어온 팔이 두 번호로 나뉨 |
| 10566665 | 남성이 세탁 세제 병을 가져감 | ✅ **세탁 세제 병 자리 사라짐 → 손님 1** |

### 만들면서 고친 것

- **사람과 물건을 다른 해상도로 탐지** — 작은 물건을 잡으려고 해상도를 1280 으로 올리자, 가까이 있는 사람이
  조각 상자 4개(신뢰도 0.17~0.47)로 잡혀 한 명이 손님 5명이 됐다. 사람은 640(신뢰도 0.8 상자 하나)으로 따로 찾는다.
- **신원 유지(계층 2) 연결** — 추적 번호 대신 매장 단위 신원을 쓴다.
- **관찰 시간 0.6초** — 1초로는 사람이 떠난 뒤 영상이 끝나기 전에 확정하지 못했다(10566665: 떠난 뒤 1.8초).
- ultralytics 는 한 모델로 `predict` 를 두 번 부르면 앞 호출의 `classes` 설정이 남는다. 물건 탐지에도 찾을 종류를 매번 명시한다.

## 한계

- **영상 2편, 사건 2건**뿐이다. 동작을 확인한 것이지 정확도를 잰 것이 아니다.
- **일반 YOLO 라 작은 물건 탐지가 흔들린다.** 10566665 에서 아무도 없을 때도 물건 수가 4~6개로 오락가락했다. 2단계 상품 모델이 필요하다.
- **팔만 들어오면 주인을 정하지 못한다.** 실제 매장 카메라처럼 사람 전체가 보이면 생기지 않을 것으로 보지만 확인 전이다.
- **두 명이 동시에 선반에 있으면 정하지 않는다.** 손이 어디로 갔는지(손목 위치)로 가르는 것은 다음 과제다.
- 겹쳐 쌓인 물건, 뒤쪽에 숨은 물건은 셀 수 없다. 진열은 한 줄로, 서로 띄워야 한다.

## 손님 기록 연결 (1-B, 2026-10-06)

선반 지도의 결과를 위험 판정의 '가져간 물건 수'로 쓴다. 전체 파이프라인(`run_tracking.py --shelf ...`)에서 돈다.

    선반 방문 결과 (ShelfVisit)                       손님 기록
    "손님 3: 10~15초, 자리 2개 비었음"         ->  물건 +2, 그 시간의 집기 동작 1번은 대신함
    "손님 4: 20~26초, 변화 없음(구경)"          ->  물건 +0, 그 시간의 집기 동작은 지움
    "손님 5: 40~45초, 자리 1개 다시 참"         ->  물건 -1 (되돌려놓음)
    "누군지 못 정함: 자리 1개 비었음"            ->  아무에게도 안 붙임, 집기 동작 수 그대로

**가져간 물건 = 선반에서 확인한 개수(가져감 - 되돌려놓음) + 선반 기록이 없는 집기 동작 수.**
- 집기 동작은 '집었을 것 같다', 선반은 '실제로 줄었다'라서, 같은 시간·같은 선반이면 선반을 믿는다.
- '구경' 방문도 기록한다. 선반 앞에 서 있었지만 아무것도 안 바뀌었다는 것이, 그 시간 집기 동작이 헛것이었다는 근거다.
- 선반에 SHELF 구역 이름을 붙이면(`--shelf 이름=x1,y1,x2,y2@구역`) 그 구역의 집기 동작만 대신한다. 선반이 여럿이면 붙이는 게 안전하다.
- 선반을 지정하지 않으면 지금까지와 똑같다 (집기 동작 수, 문구도 '집기 행동 N번').
- 판정 문구에 근거가 붙는다: `물건 2개, 결제 없음 [선반 확인 2개 가져감, 구경만 1번]`.

**실제 영상 확인** (전체 파이프라인, BoT-SORT, stride 2):

| 영상 | 정답 | 결과 |
|---|---|---|
| 10566665 | 세탁 세제 병을 가져감. 중간에 큰 통을 들었다가 다시 놓음 | ✅ `2단 1번째 bottle 사라짐 -> 손님 1`, 손님 1 물건 1개. 들었다 놓은 큰 통은 세지 않음 |
| 10566654 | 두 번째 스프레이를 가져감 (팔만 보임) | ✅ `1단 2번째 bottle 사라짐 -> 손님 1`. 1단계 시연(ByteTrack)에서는 팔이 두 번호로 나뉘어 주인을 못 정했는데, 파이프라인 기본 추적기(BoT-SORT)에서는 한 사람으로 이어져 붙었다 |

두 영상 모두 출구가 없어 최종 판정(HIGH_RISK 등)까지는 가지 않는다. 판정 규칙은 단위 테스트(`tests/test_shelf_count.py`)로 확인했다
— 한 번에 두 개, 구경만, 되돌려놓기, 선반 밖 집기, 주인 못 정함, 신원 합침, 선반 개수로 REVIEW.

**속도**: CPU 에서 13.8 → 4.8 FPS(10566665). 물건을 매 장면 전체 화면 1280 해상도로 찾기 때문이다.
실시간으로 쓰려면 선반 영역만 잘라서 찾거나, 선반 앞에 사람이 없을 때만 찾는 식으로 줄여야 한다(다음 과제).

**팀 공유 필요**: 선반을 켜면 경보의 `taken` 값이 '집기 행동 수'가 아니라 '가져간 물건 수(추정)'가 된다.
필드 이름·형식은 그대로라 경보 서버·앱은 고칠 것이 없지만, 뜻이 바뀌므로 `core/types.py` 설명은 팀에 공유한 뒤 고친다.

## 재현

```bash
# 영상: https://www.pexels.com/video/10566654/ , https://www.pexels.com/video/10566665/ (SD 버전)
#       data/videos/pexels/pexels_<ID>.mp4 로 저장
python scripts/shelf_demo.py --video data/videos/pexels/pexels_10566654.mp4 --shelf 0.05,0.25,0.70,0.97
python scripts/shelf_demo.py --video data/videos/pexels/pexels_10566665.mp4 --shelf 0.22,0.45,0.60,0.92
```
결과 이미지(변화 전/후, 사라진 자리 빨간 상자)는 `outputs/shelf_demo/` 에 저장된다.

전체 파이프라인에서 손님 기록까지 (구역 파일에 SHELF 구역 `detergent_shelf` 가 있어야 집기 동작도 나온다):

```bash
python run_tracking.py --source data/videos/pexels/pexels_10566665.mp4 --zones <구역 파일> --stride 2     --shelf "shelf1=0.22,0.45,0.60,0.92@detergent_shelf"
# 선반 방문 기록: outputs/<실행>/shelf_visits.jsonl
```
