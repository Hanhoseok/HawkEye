# RetailAction — 선반 구역 없이 자세만으로 집기를 찾을 수 있나

## 왜 했나

지금 집기 판정은 "손이 선반 구역에 얼마나 가까운가"로 판단한다(MERL, 천장 시점, `docs/merl-evaluation.md`).
매장마다 선반 구역을 손으로 그려야 하고, 구역이 없으면 판정할 수 없다.
RetailAction 은 샘플마다 손님 주변만 잘라 둔 영상이라 선반 위치를 알 수 없어서, 우리 판정기를 그대로 돌릴 수 없다.
그래서 이 데이터로는 **"선반 구역 없이 자세만으로 되는가"** 를 확인했다. 된다면 매장마다 구역을 그리지 않아도 된다.

## 데이터

Standard AI **RetailAction** test (Standard.AI Dataset License, 출처: Standard Cognition). 원본은 저장소에 올리지 않는다.

| 항목 | 내용 |
|---|---|
| 샘플 | 2,501개. 손님 한 명이 선반 앞에서 행동하는 약 9.5초 구간 |
| 영상 | 실제 미국 편의점 10곳 천장 카메라 2대, 손님 주변 600×600, 32장면(0.2~0.3초 간격) |
| 정답 | 집음 2,409 / 도로 놓음 49 / 만짐 8, 행동 없는 샘플 229. 구간 안의 시작·끝(비율)과 손이 닿은 지점 |
| 자세 | 대상 손님의 자세 좌표가 들어 있다(자체 형식, 좌표는 (행, 열)). 이번에는 이것을 썼다 |

## 방법

- 신호: **손(손목·손 중 먼 것)과 목 사이 거리 ÷ 어깨너비**. 위에서 보면 팔을 뻗을 때 손이 몸통에서 멀어진다.
- 어깨너비는 장면마다가 아니라 **그 샘플 전체의 중앙값**을 쓴다. 장면마다 재면 몸을 옆으로 돌린 순간 어깨너비가 거의 0 이 되어 값이 10배 넘게 튀었다.
- 샘플 번호 **짝수에서 방법·문턱을 고르고, 홀수에서 한 번만 채점**했다.
  고른 과정: 장면별 어깨너비 / 몸통 길이 / 샘플 중앙값 / 연속 2·3장면 조건을 짝수 쪽에서 비교 → 샘플 중앙값이 가장 나음.

## 결과 (홀수 쪽 1,250개)

**A. 언제 집었나** — 신호가 가장 큰 순간이 정답 구간(앞뒤 ±5%) 안에 드는 비율

| | 비율 |
|---|---|
| 신호 최고점 | **45.3%** |
| 아무 순간이나 고를 때 (비교 기준) | 35.9% |

**B. 헛잡기** — 행동이 있는 샘플 1,131개와 아무것도 안 한 샘플 119개를 '최대 팔 뻗음'으로 가르기

| 문턱 (짝수 쪽에서 정함) | 행동을 잡는 비율 | 아무것도 안 한 샘플을 헛잡는 비율 |
|---|---|---|
| 1.70 | 80% | **40%** |
| 1.54 | 92% | 51% |
| 1.42 | 97% | 67% |

AUC 0.77 (0.5 = 못 가름, 1.0 = 완벽).

## 결론

**자세만으로는 약하다. 선반 구역을 대신할 수 없다.**
- 집는 순간을 짚는 능력은 아무 순간이나 고르는 것보다 9%p 나을 뿐이다.
- 행동의 80% 를 잡으려면, 아무것도 안 한 손님의 40% 를 "집었다"고 본다.
- 실패 사례를 보면, 냉동고 앞에 서서 보기만 하는 손님도 팔 뻗음 값이 문턱을 넘었다.
  위에서 보면 팔을 몸 앞으로 드는 것과 선반으로 뻗는 것이 잘 구별되지 않는다.

→ "손이 **어디로** 갔는가(선반)"가 핵심 단서라는 MERL 의 결론을 다른 매장 10곳에서 반대 방향으로 확인한 셈이다.
매장마다 선반 구역을 그리는 방식은 유지해야 한다. 자세 신호는 보조 단서로만 쓸 수 있다.

## 한계

- 아무것도 안 한 샘플이 채점 쪽에 119개뿐이라 헛잡기 비율의 오차가 크다(±9%p 정도).
- 데이터에 들어 있는 자세 좌표를 썼다. 우리 파이프라인(YOLO-pose)으로 뽑으면 다를 수 있지만,
  결과가 충분히 좋지 않아 다시 뽑는 단계로 가지 않았다.
- "도로 놓음"은 49개뿐이라 되돌려놓기 감지는 시도하지 않았다(학습용 train 에 약 300개 예상, 26GB).

## 2차: 손에 물건이 있나로 집음 / 놓음 가르기 (2026-10-07)

**왜**: 집음과 놓음은 팔 동작이 같다(뻗고 넣고 거둠). 차이는 손에 물건이 **언제** 있었나 —
집음은 뻗기 전 빈손·거둔 뒤 물건, 놓음은 그 반대. 스켈레톤에는 물건 정보가 없으므로, 관절로 손 위치를 찾고
행동 직전·직후 장면의 **손 부분 사진**을 비교한다. 선반이 안 보여도, 두 사람이 있어도 쓸 수 있는 근거다(`limitations.md` D-16).

**방법** (`scripts/retailaction_hands.py`)
- 행동이 언제 일어났는지는 안다고 두고(정답 시점), **종류**만 가른다. 우리 파이프라인에서는 손 뻗기 감지가 시점을 준다.
- 어느 손인가: 행동 중 접촉점(정답의 손 닿은 지점)에 가장 가까이 간 손. 접촉점은 손 고르기와 '선반 쪽 자리'에만 쓴다.
- 특징 모델: **DINOv2-small** (Meta, Apache 2.0, 88MB). 학습하지 않고 특징만 뽑아 작은 분류기(로지스틱 회귀)를 얹는다.
  GPU 가 없고 놓음 정답이 적어서, 큰 모델을 학습시키는 대신 이 방식을 골랐다.
  (검토 후 제외: 손-물체 전용 검출기 Hands23·100DOH — Windows CPU 설치가 어렵고 1인칭 사진으로 학습,
   RetailAction 공식 영상 모델 — GPU 학습 필요, DINOv3 — 자체 라이선스·승인 필요)
- 채점: 놓음·만짐이 든 샘플 전부 + 집음만 든 샘플 무작위 600개. 같은 샘플은 같은 겹에 두는 5겹 교차검증, 씨앗 5개 평균.

**결과** — 집음 562 / 놓음 44 / 만짐 6

| 근거 | 집음 vs 놓음 AUC | 놓음 절반을 잡을 때 집음을 놓음으로 오판 |
|---|---|---|
| 관절만 (스켈레톤) | 0.60 | 29% |
| 손 부분 흑백 픽셀 | 0.57 | — |
| 손 부분을 잘라 DINOv2 | 0.58 | — |
| 선반 쪽(접촉점) 부분 DINOv2 | 0.66 | — |
| **손 자리 패치 토큰 (DINOv2)** | **0.71** | **29%** |
| 손 + 선반 쪽 패치 토큰 | 0.69 | 28% |

(AUC 0.5 = 못 가름, 1.0 = 완벽. 씨앗 간 편차 ±0.01~0.03, 놓음이 44개라 실제 오차는 ±0.05 정도로 봐야 한다)

**데이터를 늘리면?** — 학습 데이터를 25 / 50 / 75 / 100% 로 줄여 가며 같은 채점:

| 학습 데이터 (놓음 수) | 관절만 | 손 자리 패치 토큰 |
|---|---|---|
| 25% (약 8개) | 0.59 | 0.57 |
| 50% (약 17개) | 0.60 | 0.60 |
| 75% (약 26개) | 0.62 | 0.65 |
| 100% (약 35개) | 0.62 | 0.69 |

**결론**
- **손 사진에는 집음/놓음 신호가 있다.** 관절만(0.60)보다 손 자리 특징(0.71)이 낫다 — 방향은 맞다.
- **지금 수준으로는 못 쓴다.** 놓음 절반을 잡으려면 집음의 29% 를 놓음으로 잘못 본다.
- **관절만은 데이터를 늘려도 0.62 근처에서 멈추고, 손 자리 특징은 데이터가 늘수록 계속 오른다.**
  놓음 35개로 학습한 결과라, train(놓음 약 350개)을 쓰면 나아질 여지가 크다.
- 처음 방식(손 주변을 잘라 키우기)은 0.58 이었다. 손이 30px 정도라 잘라 키우면 주변(선반·몸·흐림 처리된 얼굴)이 특징을 덮었다.
  장면 전체를 넣고 손 자리의 토큰만 쓰자 0.71 이 됐다.
- 처음엔 행동이 하나인 샘플만 써서 놓음이 17개뿐이었다(놓음 49건 중 30건이 다른 행동과 같은 샘플). 행동마다 나누자 44개.

**한계**: 행동 시점을 정답으로 줬다(실제로는 손 뻗기 감지의 시점 오차가 더해진다). 만짐은 6개라 채점하지 못했다.
화면이 600x600 이고 사진이 띄엄띄엄(0.2~0.3초)이라, 우리 카메라(더 큰 해상도, 초당 여러 장)에서는 다를 수 있다.

## 재현

2차 (손 부분 사진, 특징 추출은 CPU 로 약 17분 — 나눠서 실행):

```bash
python scripts/retailaction_hands.py --start 0 --limit 220 --extract-only
python scripts/retailaction_hands.py --start 220 --limit 215 --extract-only
python scripts/retailaction_hands.py --start 435 --extract-only
python scripts/retailaction_hands.py --eval-only
```

1차:

```bash
# 데이터: https://huggingface.co/datasets/standard-cognition/RetailAction 의 data/test.tar 를
#        data/retailaction/ 에 풀기
python scripts/retailaction_eval.py --clip-scale                 # 방법 고르기 (짝수 쪽만)
python scripts/retailaction_eval.py --clip-scale --report-test   # 최종 채점 (홀수 쪽)
```
