# 직접 찍은 무인매장 영상 — 첫 시험 (2026-10-14)

정상 영상 2편으로 설정을 정하고, 절도 영상 2편은 **설정을 고치지 않고** 시험으로만 썼다.
영상은 저장소 밖 `source/` 에 있고 올리지 않는다(`.gitignore` 의 `*.mp4`). 매장 이름은 쓰지 않는다(store01).

## 영상과 정답 (눈으로 확인, `labels/store01/truth.csv`)

| 영상 | 용도 | 실제로 일어난 일 | 기대 |
|---|---|---|---|
| N01 | 설정 | 들어옴 2s → 선반 아래 단에서 갈색 병 1개 4~7s → 계산대 9~11s 결제 → 오른쪽으로 나감 12~14s | CLEAR |
| N01-1 | 설정 | 같은 흐름, 갈색 병 1개, 계산대 8~10s | CLEAR |
| T01 | 시험 | 작은 흰 상자 1개 집음 3~6s → 계산대 안 들르고 나감 7~10s | HIGH_RISK |
| T02 | 시험 | 작은 흰 상자를 집어 가방에 넣음 4~16s → 나감 17~19s | HIGH_RISK |

1920x1080, 30fps, H.265, 10~20초. 결제 시각은 결제 기록이 없어 계산대 앞에 선 동안의 가운데로 적었다.

## 정상 영상으로 정한 것

**카메라 각도 확인**
- 눈높이·수평. 사람 키 약 200px(모델 기준, 충분). 카메라는 영상 안에서 2~3.5px 만 흔들림(고정됨).
- **발이 화면에 안 나온다** — 사람 상자 아래쪽이 늘 화면 끝(y 0.99). 우리 계산대·출구 판정은 발 위치를 쓰므로 높이로는 가를 수 없다.
- 대신 **좌우 위치가 뚜렷이 갈린다** (정상 영상 실측 상자 가운데 x): 선반 앞 0.25~0.36 / 계산대 0.63~0.69 / 들어오고 나가는 곳 = 오른쪽 끝 0.82 이상.
- 선반 물건: 갈색 병은 일반 YOLO 가 bottle 0.78 로 잡음, 작은 흰 상자는 cup 0.50(N01) — 하나씩 보이는 건 아래 단의 이 두 개 정도.

**설정** (`zones/store01_N.yaml`): 선반 = 왼쪽, 계산대 = 아래 띠 x 0.55~0.78, 출구 = 아래 띠 x 0.80~1.0,
선반 영역 = 아래 단 `0.02,0.70,0.45,0.88`. 나머지(손 뻗기 3초, 선반 관찰 0.6초, 물건 점수 0.15 등)는 기본값 그대로.

**새로 넣은 규칙 — 영상 끝**: 영상이 손님이 나가고 1초 남짓 뒤에 끝나서, '출구 쪽에서 사라져 3초' 규칙으로는 판정이 하나도
안 나왔다. 녹화 파일은 끝나면 아무도 돌아올 수 없으므로, **영상이 끝날 때 출구 쪽에서 막 사라진 손님은 나간 것으로 확정**한다
(`RiskEngine.finish`, 마지막 장면에도 보이는 손님·출구가 아닌 곳에서 사라진 손님은 제외).

**정상 영상 결과**

| 영상 | 행동 판정 | 결제 | 최종 |
|---|---|---|---|
| N01 | 집음 1개 — 1단 2번째 bottle (선반+동작) | 1개 → 손님 1 | ✅ CLEAR |
| N01-1 | 집음 1개 — 1단 2번째 bottle (선반+동작) | 1개 → 손님 1 | ✅ CLEAR |

**처음으로 "결제하고 나간 손님이 통과되는가"(A-1)를 실제 매장 영상으로 확인했다.** 다만 2편이고 결제 시각은 눈으로 적었다.

## 절도 영상 시험 — 설정은 그대로, 구역만 옮김

정상 영상과 절도 영상 사이에 **카메라가 91px 옮겨지고 0.8° 돌아가 있었다**(첫 장면 배경 특징점으로 잼).
그래서 구역을 그대로 쓸 수 없어, 배경만 보고 카메라 이동을 재서 구역을 옮기는 도구를 만들었다(`scripts/transfer_zones.py`).

| 영상 | 행동 판정 | 최종 | |
|---|---|---|---|
| **T01** | 집음 1개 — 1단 1번째 cup (= 흰 상자, 선반+동작) | **HIGH_RISK** | ✅ |
| **T02** | **놓음 1개** — 생김: 1단 1번째 bottle (유령) | **CLEAR** | ❌ 절도를 놓침 |

**T02 를 놓친 이유 (2단계로 확인)**
1. 처음 돌렸을 때는 최종 판정이 아예 안 나왔다 — **구역 옮기기 도구의 오류**. 화면 아래 끝까지 그린 출구 띠를 0.8° 돌리자
   오른쪽 아래가 y 1.0 → 0.976 으로 올라가, 발이 화면 끝(0.99)에 걸린 사람이 띠 밖이 됐다. 화면 테두리는 카메라가 움직여도
   테두리이므로, 테두리에 붙은 좌표는 그대로 두도록 고쳤다(정답과 무관한 기하 오류). T01 결과는 그대로.
2. 고친 뒤에는 **CLEAR(놓침)**. 선반 지도가 틀렸다:
   - 실제로 가져간 흰 상자는 처음부터 점수 0.12~0.15 로 겨우 잡혀 **처음 배치에 들어가지 못했다** → 사라진 것도 안 보임.
   - 왼쪽 상자 더미가 처음엔 0.11(기준 미달), 끝엔 0.16~0.22 로 bottle 로 잡혀 **'생겼다'(유령)** → 놓음 1개.
   - 놓음이 손 뻗기(집기 1번)를 대신하면서 물건 수가 0 → CLEAR.
   - 선반 지도를 끄고 돌리면 손 뻗기만으로 **HIGH_RISK** (원인 위치 확인용 — 결과로 치지 않는다).

**점수 기준을 T02 에 맞춰 바꾸지 않았다.** 시험 영상에 맞추면 시험이 아니게 된다. 고칠 방향은 아래에 적고, 새 영상으로 확인한다.

## 배운 것

**시스템 쪽**
- **선반 기록이 틀리면 실제 집기를 지운다**(D-17). 선반을 동작보다 믿게 만든 설계(1-B)가, 물건 탐지가 흔들리는 곳에서는 오히려 절도를 놓치게 했다.
  고칠 후보: (a) "가져간 적 없는 손님의 놓음"은 의심 — 동작 근거로 되돌림, (b) 점수가 낮은 물건은 비교에서 빼거나 오래 유지돼야 인정,
  (c) 상품 모델(2단계). 어느 것이든 **새 영상으로 확인**해야 한다.
- 일반 YOLO 는 같은 물건도 촬영 회차·위치에 따라 점수가 크게 달라진다(흰 상자 N01 0.50 / T 0.11~0.15).

**촬영 쪽** (`filming-guide.md` 에 반영)
- **촬영 회차 사이 삼각대를 옮기지 않는다** — 바닥에 테이프로 표시. 옮겼다면 회차마다 빈 매장 보정 장면을 찍는다.
- **카메라를 2m 이상 높이고 아래로 기울여 바닥(발)이 보이게.** 지금은 좌우 위치로만 계산대·출구를 갈랐는데, 손님이 겹치거나 동선이 바뀌면 바로 무너진다.
- **나간 뒤 5초 더, 들어오기 전 3초 먼저** 찍는다. (영상 끝 규칙으로 메웠지만 실시간 판정 규칙을 그대로 시험하려면 필요)
- 작은 흰 상자처럼 **선반과 색이 비슷한 물건은 피한다** (점수 0.11~0.15). 갈색 병(0.78)처럼 대비되는 물건으로.
- 가능하면 H.264. 지금 파일은 H.265 라 프로그램은 읽지만 대시보드 라이브는 H.264 만 된다.

## 재현

```bash
# 정상 영상 (설정)
python run_tracking.py --source ../../source/N01.mp4 --zones zones/store01_N.yaml \
    --shelf "shelf1=0.02,0.70,0.45,0.88@shelf" --pay-by-dwell --panel   # (1차 때는 결제 CSV 를 썼다 — 지금은 계산대 체류 규칙)
# 절도 영상 (시험) — 구역은 배경으로 옮김
python scripts/transfer_zones.py --ref ../../source/N01.mp4 --target ../../source/T01.mp4 \
    --zones zones/store01_N.yaml --shelf 0.02,0.70,0.45,0.88 --out zones/store01_T01.yaml
python run_tracking.py --source ../../source/T01.mp4 --zones zones/store01_T01.yaml \
    --shelf "shelf1=0.000,0.698,0.412,0.890@shelf" --panel
```

# 2차 — 같은 매장 40편 평가 (2026-10-14)

영상이 40편으로 늘었다 (같은 파일 N01(1) 제외). **N 정상 13편으로 설정을 정하고 고정한 뒤**, T 절도 10편·C 복합 정상 17편을
설정을 그대로 두고 채점했다. 정답은 1초 장면표로 눈으로 적었다(`labels/store01/truth.csv`). C 는 사용자 확인: 모두 정상.

**촬영 회차가 둘**: N01~N08 은 기준 위치, N09~N12·모든 T·모든 C 는 왼쪽으로 약 90px·0.6~1.4° 회전 (같은 회차 안에서도 ±15px).
영상마다 배경으로 구역을 옮겼다(`transfer_zones`).

**결제 기록**: 결제 시스템 기록이 없어, 프로그램이 찾은 계산대 체류 구간을 1초 장면표와 대조해(13편 모두 일치) 체류마다 1개 결제를 넣었다.
계산대에 안 간 정상 손님은 '집은 것 없음'으로 본다.

**평가 도구** `scripts/store_eval.py`: run(영상 실행·기록) → pay(계산대 체류) → judge(저장된 기록으로 판정만, 몇 초).
물건 탐지 결과를 남겨(`--shelf-log`) 선반 설정을 바꿔도 영상을 다시 안 읽는다. 1080p 를 CPU 로 돌려 2장에 1장만 처리했다.

## 틀린 원인

| 틀림 | 수 | 원인 |
|---|---|---|
| 절도 놓침 | 6 | **선반이 '그대로'(만지기만·구경)라고 해서 진짜 손 뻗기를 지웠다** (T01·T02·T03-1·T03-2(1)·T08·T10-2). 가져간 작은 흰 상자는 점수가 낮아 지도에 없거나, 그 자리의 희미한 탐지로 '아직 있다'가 됐다 |
| 거짓 경보 (C) | 11 | **선반 기록 없이 머묾(손 뻗기)만으로 경보** — 이 매장 손님은 구경할 때도 물건을 들어 보며 3초 넘게 멈춘다. 대부분 두 사람이 함께 선반을 가려 선반 변화를 누구에게도 못 붙였다 |
| 거짓 경보 (C) | 2 | 선반 거짓 '사라짐' (C10·C16) |
| 거짓 경보 (N) | 1 | N09 — 위와 같은 두 사람 경우 |

**두 근거가 반대 방향으로 틀린다**:
- 손 뻗기(머묾)는 **구경에도 켜진다** — 특이도가 없다 (D-1).
- 선반 지도는 **가져간 물건을 못 보고**(일반 YOLO, D-14), **두 사람이면 누구 것인지 못 정한다**(D-11).
- '선반을 동작보다 믿는' 규칙(1-B) 때문에 절도에서는 선반의 '그대로'가 집기를 지우고(D-17), 정상에서는 선반이 비면 머묾이 그대로 경보가 된다.

## 다음에 필요한 것 (제안)

1. **상품 탐지 모델** (2단계): 이 매장 물건(흰 상자·병 등)을 학습시켜 선반 개수를 믿을 수 있게. 이번 40편이 학습·평가 재료가 된다.
2. **손에 물건이 있나** (손 사진 — RetailAction AUC 0.71, 데이터가 늘수록 오름): 구경(빈손으로 떠남)과 집기(들고/숨기고 떠남)를 직접 가르는 근거.
3. **카메라를 높여** 두 사람이 선반 앞에 있어도 손이 누구 것인지 보이게 (B-9).
4. 그때까지는 **근거가 약하면 HIGH_RISK 대신 REVIEW** 로 낮추는 정책 검토 — 경보를 줄이는 것이지 구분력을 높이는 것은 아니다.

# 3차 — 기능별 평가 (2026-10-14, 촬영 목적 확인 뒤)

사용자 확인 두 가지로 평가를 다시 짰다.
- **C 는 사람 추적 확인용 정상 영상**이다 (비슷한 옷, 화면 밖으로 나갔다 들어옴). 2차에서 C 를 "경보가 안 나야 정답"으로 채점한 것은
  **결제 기록이 없는데 '계산대에 안 간 사람은 아무것도 안 가져갔다'고 내가 가정한 탓**이라 목적에 맞지 않았다 → C 는 추적만 채점.
- **결제 기록은 없다. 계산대에 서 있으면 결제, 그 뒤 다시 상품 쪽으로 가면 취소**로 본다 → 프로그램 규칙으로 넣음
  (`risk.payment_mode: dwell`, 계산대 1.5초 이상 = 결제, 결제 뒤 몸이 선반 구역과 50% 이상 겹치면 취소, `--pay-by-dwell`, 테스트 5개).

정답은 1초 장면표, 신원별 사진 모음, **영상 처음·끝 선반 비교**로 눈으로 적었다(`labels/store01/truth_functions.md`).
아래 선반 물건 이름: **병**(갈색 병), **흰 상자**(작은 흰 상자), **흰 카드**(선반 오른쪽 끝 흰 삼각 포장 2개).

### T08 정정과 놓친 이유 (2026-10-14)

T08 은 위장 결제가 아니라 **결제한 뒤 다른 물건을 훔치는 장면**이다 (사용자 확인):
흰 상자 집음 4~7s → 계산대 8~13s (결제) → 선반 오른쪽 끝으로 돌아가 흰 카드 집음 14s → 나감.

규칙대로라면 잡힌다 — 결제 뒤 선반으로 돌아갔으니 결제가 취소되고(또는 흰 카드가 결제 안 된 물건으로 남고) 나가면 경보.
놓친 것은 **결제 규칙이 아니라 탐지** 때문이다:
1. 흰 상자를 선반이 못 봐 '변화 없음' → 첫 손 뻗기가 지워짐 → 계산대에 갈 때 가진 물건이 0 개라 결제할 것도 없음.
2. 두 번째(흰 카드)는 선반 앞 1초뿐이라 손 뻗기(3초 머묾)가 안 잡힘, 흰 카드는 선반도 못 봄.
선반 기록을 끄면(손 뻗기만) 첫 손 뻗기가 남아 결제 → 선반으로 돌아가 취소 → 나감 = HIGH_RISK 가 나온다.

남은 설계 문제: '결제 뒤 선반으로 가면 취소'는 N06(되돌려놓음)과 T08(더 훔침)을 둘 다 경보 쪽으로 보낸다.
N06 처럼 물건을 **도로 놓으면** 그 물건만 빼고, T08 처럼 **더 집으면** 그 물건만 결제 안 된 것으로 보는 게 실제에 가깝다 — 선반이 물건을 볼 수 있어야 가능.
