# 4차 촬영 · 최종 시연 준비 — 3차까지에서 배운 것

작성 2026-11-13 · 근거 기록은 `docs/multiview-progress.md` 후속 18~32, `docs/shoot2-vs-shoot3.md`
촬영 일반 안내(카드·역할·정답표 양식)는 `docs/filming-guide.md` — 이 문서는 2·3차 결과에서 나온 **추가·변경 사항**만 적는다.

## 0. 한눈에

- 목표: 특정 영상 세트 점수가 아니라 **4차 촬영과 최종 시연에서 그대로 통하는 것**.
- 시연 방식: **현장 실시간이 1순위**, 안 되면 미리 찍은 영상을 처리해 보여 준다 (§4).
- 지금 오답의 절반쯤은 코드가 아니라 **촬영 조건·준비 절차**에서 나왔다 → 촬영 점검표(§1)가 가장 싸고 효과가 크다.
- 4차는 **시험용**으로 잠근다: 규칙·설정을 촬영 전에 고정하고 한 번 돌린 점수를 최종 숫자로 쓴다 (§3).

## 1. 촬영할 때 고칠 것

### 1-1. 카메라

| 항목 | 3차까지 있었던 일 | 4차·시연에서 |
|---|---|---|
| 고정 | 영상마다 카메라가 조금씩 움직여 영상별로 구역을 옮겨 맞춤 (register.csv) | 삼각대·거치대로 고정, 촬영 중 손대지 않기. 움직였으면 그 자리에서 보정 장면을 다시 찍기 |
| 프레임 속도 | 전체 카메라(angle1)가 장면을 빠뜨려 실제 시각표를 따로 읽음 | 프레임 속도·노출을 고정으로 잠그기 (자동 끄기) |
| 두 카메라 시각 | 시차를 눈으로 맞춤 | 영상마다 시작할 때 박수 한 번 또는 손전등 깜빡임 — 두 카메라에 함께 보이게 |
| 선반 카메라 각도 | 자리·선반 모양이 바뀌자 꺼냄을 덜 봄 (영상만 절도 2/9 → 다시 돌려 4/9) | 몸에 손이 가려지지 않는 높은 옆쪽·위쪽. 레인 경계가 화면에 보이게. 세팅 직후 시험 꺼냄 3번으로 확인 |
| 문 위치 | 3차는 문이 화면 가운데, 통로 구역이 문을 덮음 | 문 안쪽 바닥과 문 밖이 화면에서 구분되게. 문턱에 바닥 테이프 |

### 1-2. 화면 안 정리

- **옷 더미·가방**: 의자·탁자 위 재킷이 사람으로 잡혔다 (C05·C14). 화면 안에서 치운다.
- **유리 밖 행인**: 유리에 시트·블라인드를 치거나 유리가 화면에 덜 들어오게 각도를 잡는다.
- **스태프 위치**: 입구에 서 있던 사람이 손님으로 세어졌다 (T05). 촬영 안 하는 사람은 화면 밖.
- **빈 매장 영상 30초**: 세팅 직후 사람 없는 매장을 찍어 둔다 — 여기서 사람으로 잡히는 자리는 전부 가짜 (§2-2).

### 1-3. 촬영 진행

- **앞뒤 여유**: 입장 5초 전부터 찍고, 모두 나간 뒤 5초 더. '영상 끝' 예외 규칙이 필요 없어진다.
- **시나리오 번호 카드**: 영상 시작 때 카메라에 보여 준다. 파일 이름·정답표와 엇갈리지 않게.
- **정답 즉석 기록**: 인원, 누가 어느 레인에서 몇 개, 결제 몇 건·몇 개, 나갔다 돌아온 사람 여부 — 촬영 직후 적는다.
  3차 정답표는 2차 것을 가져온 상태라 인원·정답이 영상으로 확인 안 된 짝이 있다.
- **옷**: 검은 상의 2명은 생김새로 못 가린다 (C13 — 돌아온 사람이 엉뚱한 신원과 더 비슷하게 나옴).
  '비슷한 옷' 세트와 '다른 옷' 세트를 **나눠** 찍어 어디까지 되는지 숫자로 말한다. 시연은 다른 옷.
- **긴 연속 촬영**: 지금 평가는 전부 20~40초 토막. 손님 여러 팀이 이어서 드나드는 **5분짜리를 1~2개** 넣는다 (시연과 같은 조건).

### 1-4. 센서·결제

- **센서 사전 점검**: 3차 센서는 누락·지연·가짜가 섞였다 (L3 는 못 믿어 뺌). 촬영 전 레인별로 꺼냄·놓음을 10번씩 해 기록이 맞는지 확인.
- **무게 원값 저장**: 이벤트(REMOVE·ADD)만이 아니라 무게 원값도 남긴다 — 나중에 이벤트 판단을 다시 할 수 있게.
- **센서 시계 기준**: 영상마다 시작 때 정해진 레인에서 한 번 꺼냈다 놓기 → 센서 시각 ↔ 영상 시각을 자동으로 맞춘다.
- **결제 기록**: 바코드 삑 소리 방식은 통했지만(39편 초안 → 사람 확인) 조용해야 한다.
  스캐너 입력을 **시각과 함께 파일로** 남기면 결제 개수 문제(T04~T06)가 소리 없이 풀린다. 삑 소리는 예비로 유지.

보류 판정(2-1)은 계속 돌아가는 시연에서 **경보 → 돌아와 결제 → 취소** 흐름으로 꼭 필요하다. 대가는 경보가 보류 시간(예: 5초)만큼 늦는 것.

적용 안 한 것: '집기 동작만' 근거 HIGH_RISK 를 REVIEW 로 낮추기 — 3차 거짓 경보는 줄지만 2차 실제 절도 C2·T9 를 놓친다 (후속 32).

## 3. 평가 방식

- **세트 역할**: 2차 = 개발용, 3차 = 이미 여러 번 들여다본 확인용, **4차 = 시험용(잠금)**.
  4차는 규칙·설정·구역 그리는 절차를 촬영 전에 고정하고, 처음 한 번 돌린 점수를 최종 숫자로 보고한다.
- **회귀 검사 한 줄**: 모든 촬영을 돌려 기준선과 달라진 짝(점수·손님 수·판정)을 뽑는 스크립트. 지금은 손으로 비교했다.
- **탐지·추적 결과 저장**: 신원 규칙 하나 바꿀 때마다 촬영당 약 1시간 다시 돌렸다. 탐지·추적 결과를 저장하고 신원·판정만 다시 계산하면 몇 분.
- **세트 나눠 보고**: 한 사람 / 두 사람(다른 옷) / 두 사람(비슷한 옷) / 나갔다 돌아옴 / 건네고 대신 계산 — 어디서 되고 어디서 안 되는지 따로.

## 4. 최종 시연

### 4-1. 방식

1. **현장 실시간** (1순위) — 카메라 2대 → 실시간 입력(`src/inputs/live_source.py`, 최신 장면만 처리) → 상황판(`src/viz/live_panel.py`).
2. **미리 찍은 영상 처리** (예비) — 같은 장소에서 미리 찍어 처리한 결과를 재생. 실시간이 실패하면 바로 전환.

### 4-2. 실시간이 되려면

- 지금 처리 속도 (이 컴퓨터, CPU 전용 torch): 3차 39편 평균 26.9초짜리 한 짝에 85초, 2차 평균 22.0초에 69초 → **실시간의 약 1/3 속도**.
  이때 처리 간격은 전체 카메라 60fps 중 4장에 1장, 선반 카메라 30fps 중 2장에 1장 (둘 다 초당 15장).
- 실시간 입력은 밀리면 장면을 건너뛴다. **잰 결과 (후속 34)**: 카메라당 초당 3.6장(3차)·2.8장(2차), 처리 지연 약 0.25초.
  총점은 녹화본과 비슷(3차 27/39, 2차 30/38)하지만 짝별 결과가 흔들리고 절도를 덜 잡는다(3/9 씩). 다른 작업이 CPU 를 같이 쓰면 초당 1장 아래로 떨어진다.
- 할 일 (순서대로):
  1. ~~2·3차 녹화본을 실시간 속도로 흘려 점수를 잰다~~ — `scripts/live_sim.py --shoot 2|3` 완료. 지금 CPU 로는 위험.
  2. 안 되면: GPU 노트북 / 처리 해상도 낮추기 / 처리 간격 늘리기 중에서 점수를 지키는 조합을 찾는다.
  3. 그래도 안 되면 예비 방식(미리 찍은 영상)으로 확정.
- 실시간에는 '영상 끝'이 없다 → 판정은 전부 '문으로 나감' 기준이어야 하고, 보류 판정(2-1)과 신원 정리(오래된 신원 지우기)가 5분 넘게 돌아도 멀쩡해야 한다. 4차의 긴 연속 촬영으로 확인.
