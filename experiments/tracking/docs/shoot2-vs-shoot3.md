# 2차 vs 3차 촬영 — 절도 판정 비교

작성 2026-11-12 · 자세한 기록은 `docs/multiview-progress.md` 후속 18~24

## 1. 한눈에

| 판정 | 전체 | 정상 N | 복합 정상 C | 절도 T | 판정 없는 짝 |
|---|---|---|---|---|---|
| 2차 영상만 | 31/38 | 11/12 | 16/17 | 4/9 | 8 |
| 2차 + 결제 라벨 | 30/38 | 11/12 | 15/17 | 4/9 | 8 |
| 3차 영상만 | 27/39 | 10/12 | 15/18 | 2/9 | 2 |
| 3차 센서(L1·L2) + 영상 | 28/39 | 9/12 | 13/18 | **6/9** | 2 |
| 3차 센서(전 레인) + 영상 | 28/39 | 10/12 | 12/18 | 6/9 | 2 |

정답이 같은 **공통 37짝**만 세면: 2차 **30** · 3차 영상만 **26** · 3차 센서(L1·L2) **27**

> 빼고 센 짝: C02 (2차 정답 절도 — 한 명이 결제 없이 먼저 나감 / 3차 정답 정상), C16 (3차에만 있음).

**요약**
- 2차는 판정 규칙·구역을 만들며 계속 본 **개발용** 영상, 3차는 그 규칙을 처음 적용한 **새** 영상 → 3차가 실력에 더 가까운 숫자.
- 새 영상에서 영상만 판정은 30 → 26 으로 떨어졌다. 선반 카메라 자리·선반 모양이 바뀌자 꺼냄을 덜 본다.
- 센서는 그 빈자리를 메워 절도를 2차보다 많이 잡지만(6 vs 4), 두 사람 장면에서 주인을 잘못 정해 정상 오답이 는다.
- 두 회차 공통 병목: **결제 개수 기록**(T04~T06) · **두 사람 장면의 주인 정하기**(N09 등).

## 2. 두 촬영의 차이

| | 2차 (2026-10-28) | 3차 (2026-11-11) |
|---|---|---|
| 영상 수 | 38쌍 | 39쌍 (C16 추가, 2차와 같은 시나리오 이름) |
| 선반 | 열린 선반 (카드·병·빵 상자) | 센서 레인 받침 — 뒤에서 밀어 주는 칸 3개 (L1 칸타타 · L2 동과루 · L3 애플사이다) |
| 선반 카메라(angle0) | 선반을 보는 자리 | 손님 **등 뒤**에서 받침을 봄 — 집는 순간 약 1/3 이 몸에 가림 |
| 전체 카메라(angle1) | 출구가 화면 **끝** | 출구가 화면 **가운데** (삼각대 옆 벽 뒤) |
| 전체 카메라 영상 | 장면 일정 | 장면을 빠뜨림 (39편 중 31편, 중간 최대 2.5초 어긋남) |
| 카메라 움직임 | — | 영상마다 조금씩 움직임 (선반 카메라 레인 자리에서 최대 약 27px = 레인 하나 폭) |
| 센서 | 없음 (시험용 가짜 4편) | 실제 레인 센서 — L1·L2 가짜 0·놓침 11%, **L3 는 못 믿음** (가짜 21) |
| 결제 기록 | 결제 라벨 있음 | 없음 — 계산대에 머문 시간 = 결제 |

3차에 맞춰 바꾼 것 (2차 결과는 짝별로 완전히 같음을 확인):
- 실제 장면 시각 사용, 구역 파일을 영상마다 카메라 위치로 옮김, 두 카메라 잇기 값을 카메라 움직임을 되돌린 좌표로.
- 출구 규칙: 영상 끝에 출구 구역 안이면 나가는 중 (3차에서만 — 출구가 화면 가운데라서).
- 판정 값(머무는 초 등)은 두 회차 모두 코드 기본값 그대로.

## 4. 무엇이 갈랐나

### 4-1. 두 회차 모두 놓친 절도 — T04 · T05 · T06
- 계산대를 쓰는 절도: 일부만 결제(T04) · 수량을 적게 결제(T05) · 결제 미완료(T06).
- "계산대에 머물면 가진 것 모두 결제" 규칙으로는 가릴 수 없다 (3차 T05 는 물건 1개에 결제 3개로 셈).
- 2차에 결제 라벨을 넣어도 4/9 그대로. 3차 센서가 꺼낸 개수를 맞혀도(T04 물건 4개) 몇 개를 결제했는지 모르면 소용없다.
- → **결제 개수가 남는 기록**(키오스크 로그 또는 결제 라벨)이 필요.

### 4-2. 2차는 잡고 3차 영상만은 놓친 절도 — T01 · T09 · T10
- 3차 선반 카메라는 손님 등 뒤에서 받침을 본다 → 집는 순간 약 1/3 이 몸에 가림.
- 밀어 주는 칸이라 하나 꺼내도 앞 상품이 그대로 앞에 남는다 → 줄어든 게 보이는 곳은 뒤쪽 뚜껑 개수뿐.
  레인 그림 비교의 재현율 51%, 판정 근거로 확인된 '집음'은 정답 66개 중 **13개**.
- 2차는 열린 선반이라 빠진 게 보였다.
- 3차에서 센서를 넣으면 셋 다 잡힌다 (T08 도 추가로).

### 4-3. 판정 없는 짝 8 → 2
- 3차는 출구 규칙을 고쳐 거의 다 결론이 난다.
- 그래서 2차에서 "판정 없이 맞음"으로 가려지던 종류의 오답이 드러난다:
  N06 (결제 취소 후 반납) · N11 (비교 후 모두 반납) — **되돌려 놓은 걸 다 세지 못함**.
  (N11: 정답은 꺼냄 2 · 되돌림 2 인데 센서로도 꺼냄 3 · 되돌림 2 로 셈.)

### 4-4. 정상 오답 — 원인은 같다
| 원인 | 2차 | 3차 영상만 | 3차 센서 |
|---|---|---|---|
| 두 사람 장면에서 꺼냄 주인을 잘못 정함 | N09 · C12 | — | C06 · C15 · N09 |
| 꺼냄(확인 못 한 집기 동작)이 결제와 안 이어짐 | — | C01 · C13 | C01 · C13 |
| 되돌림을 다 못 셈 | — | N06 · N11 · C16 | N06 · N11 · C16 |

- N09 (A 가 집어 B 에게 건네고 B 가 결제) 는 2차·3차(센서) 모두 틀림 — 꺼냄이 A 에게 붙고 B 의 결제와 안 이어진다.
- 3차 영상만에서 맞은 정상 25편 중 **19편은 꺼낸 걸 못 봐서** 정상으로 나온 것 (꺼냄을 보고 결제로 맞힌 것 6편).
  센서(L1·L2)를 넣으면 맞은 정상 22편 중 18편이 꺼냄을 보고 결제로 맞힌 것 (못 보고 맞은 것 4편).

### 4-5. 센서가 만든 차이 (3차)
| | 영상만 | 센서 L1·L2 + 영상 |
|---|---|---|
| 판정 근거로 확인된 꺼냄 (정답 66개 중) | 13 | 53 |
| 절도 | 2/9 | 6/9 |
| 정상 + 복합 정상 | 25/30 | 22/30 |

- 좋아짐: T01 · T08 · T09 · T10 — 선반 카메라는 "변화 없음"인데 센서가 꺼냄을 알려 줌.
- 나빠짐: C06 · C15 · N09 — 센서는 "언제·어느 레인·몇 개"만 알고 "누가"는 영상 짝짓기에 맡김 → 두 사람 장면에서 엉뚱한 사람에게.
- L3 센서까지 쓰면 C21 이 L3 가짜 꺼냄으로 추가로 틀림 → **L3 는 빼는 게 낫다**.

## 5. 결론과 다음 할 일

1. **결제 개수 기록** — T04~T06 은 두 회차·모든 판정에서 놓침. 판정 규칙이 아니라 입력이 없어서.
2. **두 사람 장면에서 누가 가져갔는지** — 센서 효과를 깎아 먹는 주 원인 (C06 · C15 · N09).
3. **되돌림 세기** — 출구 판정이 결론을 내자 드러난 정상 오답 (N06 · N11 · C16).
4. 선반 카메라만으로 꺼냄을 보는 건 3차 배치(등 뒤 카메라 · 밀어 주는 칸)에서 한계가 크다 → 센서(L1·L2)를 판정 근거로 쓰는 쪽이 맞다.

## 6. 주의할 점

- 3차 바닥 구역은 첫 결과(13/39)를 본 뒤 한 번 다시 그렸다 — 처음 초안은 카메라 자리가 다른 area_setting 장면 기준이라 계산대가 선반 자리에 가 있었다.
  구역 위치는 사람 발 분포로 정했고 판정 값은 안 바꿨지만, 3차 점수는 다소 낙관적일 수 있다.
- 2차도 구역 편집 페이지로 판정을 보며 구역을 고친 적이 있어 개발용 영상이다.
- 2차 "결제 라벨" 결과(30/38)는 지금 코드로 다시 돌린 값.
- 3차 정답: T 절도, N·C 정상 (사용자 확인). 인원은 2차 같은 짝에서 가져옴, C16 은 1명 추정.
