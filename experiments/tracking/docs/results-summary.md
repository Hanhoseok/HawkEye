# tracking 결과 종합 (2026-10-14 기준)

팀원 공유용. 지금까지 만든 기능과 **직접 찍은 매장 영상 40편**으로 잰 결과를 한 장에 모았다.
자세한 근거는 각 문서, 무엇이 안 되는지는 `docs/limitations.md`.

---

## 1. 무엇을 만들었나 — 한 프로그램, 한 장면씩

```
영상 한 장면
  ├─ ① 사람 추적      YOLO(사람) → BoT-SORT(장면 사이 잇기) → 매장 단위 신원("손님 1")
  ├─ ② 행동 (손 뻗기)  선반 구역 앞에 멈춤 / 손목-선반 거리 → "손님 1, 3~7초 손 뻗음"
  └─ ③ 선반 상태      YOLO(물건, 1280) → 선반 지도 → 가림 → 떠난 뒤 비교 → "1단 2번째 병 사라짐"
        ↓
  ④ 손님 장부   ②+③ → 집음 / 놓음 / 만지기만 · 물건 수 · 결제(계산대 체류)
  ⑤ 판정        출구에 다가서면 WARNING, 나가면 HIGH_RISK / REVIEW / CLEAR
  ⑥ 출력        기록 파일 · 상황판 화면(--show) · 관리자 앱 경보(app-pos)
```

- 실행: `python run_tracking.py --source <영상> --zones <구역> --shelf "<선반 영역>" [--pay-by-dwell] [--show]`
- 모델은 모두 공개 사전학습 모델 그대로(YOLOv8n, YOLOv8n-pose, OSNet). **판단은 전부 규칙**이고 기준값은 데이터로 재서 골랐다(학습용·채점용 분리).
- 결제 기록이 없는 매장: **계산대에 1.5초 이상 서 있으면 결제, 그 뒤 다시 상품 쪽으로 가면 취소** (`--pay-by-dwell`).

## 2. 검증에 쓴 영상

| 영상 | 쓰임 | 문서 |
|---|---|---|
| **직접 찍은 매장 영상 40편** (N 정상 13 · T 절도 10 · C 추적 확인용 정상 17) | 기능별 최종 평가 | `store-test.md` |
| MERL (천장 카메라, 손 뻗기 라벨) | 손 뻗기 정량 평가 | `merl-evaluation.md` |
| UCF-Crime 절도 CCTV (039·047) | 출구 판정·혼잡 | `risk-pipeline.md` §6 |
| Pexels 선반 영상 3편 | 선반 지도·집음 판정 | `shelf-map.md` |
| RetailAction (편의점 10곳, 집음/놓음 라벨) | 손 사진으로 집음/놓음 가르기 시험 | `retailaction-eval.md` |

매장 영상 평가 방식: **정상 N 13편으로 설정을 정하고 고정**한 뒤 T·C 는 설정을 바꾸지 않고 채점. 정답은 1초 장면표·신원별 사진·처음/끝 선반 비교로 눈으로 적음
(`labels/store01/truth_functions.md`). 영상 파일은 저장소에 올리지 않는다.

## 3. 매장 영상 40편 — 기능별 결과

| 기능 | 대상 | 결과 | 평가 |
|---|---|---|---|
| **사람 추적** | N·T 23편 (대부분 1명) | 사람 수·신원 **23/23** | ✅ |
| | C 17편 | 끝까지 깨끗 **9/17** · 번호 뒤바뀜 5 · 한 사람이 둘로 쪼개짐 3 | ⚠️ |
| | 화면 밖에 나갔다 돌아온 사람 | **2/4** 이어 붙임 | ⚠️ |
| | 비슷한 옷 (흰 티 2명) | 4편 중 1편만 버팀 | ❌ |
| **행동** | 손 뻗기 (손님 25명) | **21/25**, 1~2.5초 짧은 집기 놓침 | ✅ |
| | 집음 vs 들어 보고 놓기 | 손 뻗기만으로는 못 가름 (선반 판단에 의존) | ⚠️ |
| **선반 상태** | 갈색 병 사라짐 | **8/8** | ✅ |
| | 작은 흰 상자 | **4/10** | ❌ |
| | 흰 카드 (선반 오른쪽 끝) | **0/5** | ❌ |
| | 되돌려놓기 / 아무것도 안 빠짐 | 1/1 · 1/1 | ✅ |
| | 거짓 '사라짐' | 2건 | ⚠️ |
| **절도 판정** | 절도 T 10편 (HIGH_RISK 가 나와야) | **4/10** | ❌ |
| | 정상 N 13편 (경보 없어야) | **12/13** | ✅ |
| | 참고: 선반 판단 끄고 손 뻗기만 | 절도 9/10, 정상 거짓 경보 2 | |

**왜 절도를 놓쳤나** — 놓친 6편 중 5편은 손 뻗기는 잡았는데, **가져간 물건(흰 상자·흰 카드)을 선반이 못 봐 '변화 없음'으로 판단 → 손 뻗기를 지웠다.**
나머지 1편(T03-2(1))은 선반 앞 2.5초라 손 뻗기도 놓쳤다.
T08(결제한 뒤 다른 물건을 훔침)도 같은 이유 — 규칙상으로는 잡혀야 하는 장면이다(결제 뒤 선반으로 돌아가면 취소).

## 4. 그 밖의 결과 (공개 데이터)

| 항목 | 결과 |
|---|---|
| 손 뻗기 (MERL test, 천장) | 정밀도 0.75 / 재현율 0.71 / F1 0.73 |
| 출구 판정 (UCF 039, 실제 절도 CCTV) | 도둑만 WARNING → HIGH_RISK, 나머지 CLEAR |
| 혼잡 (UCF 047) | 경보 두 단계 + 판정 직전 신원 확인으로 오경보 2 → 0 |
| 선반 지도 (Pexels 3편) | 3/3 '집음 1개' 정답, 들었다 놓은 큰 통은 안 셈 |
| 손 사진으로 집음/놓음 (RetailAction) | AUC 0.71 (관절만 0.60) — 아직 못 씀, 데이터 늘수록 오름 |
| 경보 전송 | app-pos 서버·대시보드까지 UCF 039 로 끝까지 확인 |
| 속도 (CPU) | 선반 확인 켠 상태 4.8 → 10~11 FPS (가린 동안 물건 탐지 건너뜀), 1080p 는 약 3 FPS |

## 5. 정리 — 되는 것과 안 되는 것

- **사람 한 명 추적, 손 뻗기, 일반 물체(병) 선반 확인, 결제(계산대 체류) 연결, 경보 전송까지 한 프로그램으로 돈다.**
- **안 되는 것**: 이 매장의 작은 흰 물건을 못 본다 → 선반이 손 뻗기를 지워 절도를 놓친다. 비슷한 옷·재입장 추적이 약하다.

## 6. 다음 단계 (제안)

| 순서 | 할 일 | 해결되는 것 | 필요한 것 |
|---|---|---|---|
| 1 | **이 매장 물건으로 상품 탐지 모델 학습** | 선반이 흰 상자·흰 카드를 봄 → 선반·행동·절도 판정 동시 개선 | 40편에서 물건 라벨, GPU(Colab) |
| 2 | 선반이 볼 수 있는 자리에 손이 갔을 때만 '변화 없음'으로 손 뻗기를 지움 + 짧은 손 뻗기 잡기 | 학습 전 임시로 놓침 감소 | N 영상으로 먼저 확인 |
| 3 | 결제 뒤 행동 구분 — 도로 놓으면 그 물건만 빼고(N06), 더 집으면 그 물건만 미결제(T08) | '선반으로 가면 전부 취소'보다 실제에 가까움 | 1 이 선행 |
| 4 | 추적 보강 — 신원 비교 기준, 카메라 높이 | 비슷한 옷·재입장 | 재촬영 시 카메라 2m 이상 |

## 7. 재현

```bash
cd experiments/tracking
# 매장 영상 일괄 평가 (영상은 저장소 밖 ../../source/)
python scripts/store_eval.py run          # 영상마다 실행·기록 (CPU 로 영상당 1~2분)
python scripts/store_eval.py judge        # 저장된 기록으로 판정만 (몇 초)
python scripts/store_eval.py judge --no-shelf   # 진단: 선반 판단 없이
# 한 편을 상황판으로 보기
python run_tracking.py --source ../../source/T01.mp4 --zones zones_store01_T01.yaml \
    --shelf "shelf1=0.000,0.698,0.412,0.890@shelf" --pay-by-dwell --show
```
