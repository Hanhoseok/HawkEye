## 여기 있는 것 / 없는 것

- `classes.yaml` — 종류 3개와 번호: 0 칸타타(cantata) · 1 동과루(donggwaru) · 2 애플사이다(applecider). 레인 L1 · L2 · L3 와 같은 순서.
  1종이 아니라 3종으로 찍기로 했다 (사용자 결정). 3종 라벨은 나중에 1종으로 합칠 수 있지만 반대는 안 된다.
- `frames.csv` — 쓸 장면 표. 한 줄이 한 장: 그림 이름 · 영상 · 카메라 · 장면 번호 · 시각 · 고른 까닭 · 레인 · 사람 수 · 나눔 · 묶음.
- `boxes/<그림 이름>.json` — 라벨. 그림마다 파일 하나, 상자 하나가 한 줄. 얼굴이 없으므로 저장소에 올린다.
- **그림은 없다.** 얼굴이 나오므로 저장소에 올리지 않는다. `outputs/products_shoot3/images/` 에 뽑힌다 (영상이 있으면 누구나 같은 그림을 다시 뽑는다).
- 학습된 모델도 올리지 않는다 (`.gitignore` 의 `*.pt`).

## 라벨 찍기 (분석 도구 → '상품 라벨')

```
python workbench/server.py                  # http://127.0.0.1:8770/ → 위쪽 '상품 라벨'
python scripts/product_frames.py export     # 다 찍은 것을 YOLO 학습용으로 → outputs/products_shoot3/data.yaml
```

- 목록: 칸 하나가 한 장 (안 찍음 · 찍는 중 · 끝). '이어서 찍기'가 남은 첫 장을 연다.
- 한 장: 빈 곳을 끌면 상자, 1 · 2 · 3 으로 종류, 상자를 눌러 고르고 옮기기 · 테두리 끌어 크기 · Del 지우기 · H 손에 든 상품. 휠로 확대 (상품이 작아 확대가 필요하다 — 확대한 자리는 같은 카메라의 다음 장에서도 그대로).
- 고칠 때마다 저절로 저장된다 (**찍는 중**). **Enter 를 눌러야 '끝'** 이고, 학습에는 끝난 장면만 들어간다 — 덜 찍은 장면은 안 찍힌 상품을 '상품 아님'으로 가르치기 때문이다.
- 상자가 없는 채로 Enter = '상품이 안 보인다' (배경 장면으로 학습에 들어간다). X = 이 장면은 학습에서 뺀다 (흐려서 모를 때).
- **초안**: 안 찍은 장면을 열면 같은 카메라에서 끝낸 가장 가까운 장면의 상자가 점선으로 깔린다 (손에 든 것은 빼고). 없어진 상품은 지우고 자리를 맞춘 뒤 Enter.

찍는 기준 (화면에도 적혀 있다 — 내가 정한 기본값이고 바꿀 수 있다):

1. 보이는 상품은 전부 찍는다.
2. 절반 넘게 가린 것은 안 찍는다.
3. 상자는 보이는 부분에 딱 맞게.
4. 손에 든 상품도 상자를 찍는다. 손에 든 표시(H)는 안 해도 된다 (사용자 결정 2026-11-17 — 학습에 안 쓰이고, 상품이 무엇인지만 알면 된다).
5. 흐려서 무엇인지 모르면 그 장면을 뺀다.

라벨 파일:

```
{"image": "C01_angle0_00196.jpg", "width": 1920, "height": 1080, "done": true, "skip": false, "boxes": [
 {"cls": 1, "x1": 1119.0, "y1": 374.0, "x2": 1145.0, "y2": 428.0, "held": false}
]}
```

좌표는 그림 픽셀, `cls` 는 `classes.yaml` 의 번호. `export` 는 이것을 YOLO 형식(`cls cx cy w h`, 0~1)으로 바꿔 그림 옆 `outputs/products_shoot3/labels/` 에 쓰고
나눔별 목록(`train.txt` · `val.txt` · `test.txt`)과 `data.yaml` 을 만든다. 그림은 복사하지 않는다.

그대로 학습에 넣으면 안 되는 점 (아래 '바꾼 것'에서 고쳤다):

1. **나눔이 장면 단위다.** 34편 전부가 train · valid · test 에 걸쳐 있고, 옆 장면 1,160쌍 중 554쌍이 서로 다른 쪽이다. 옆 장면은 거의 같은 그림이라 이대로면 검증 · 시험 점수가 실제보다 높게 나온다. → 우리 표(`frames.csv`)의 영상 단위 나눔으로 다시 나누면 학습 746 · 검증 133 · 시험 293장 (`area_setting` 22장은 정해야 한다).
2. **종류 번호가 다르다.** Roboflow: 1 apple soda · 2 cantata · 3 donggwaru (0 `labeling` 은 안 쓰는 묶음 이름). 우리 `classes.yaml`: 0 칸타타 · 1 동과루 · 2 애플사이다. → 이름으로 맞춰 옮긴다.
3. **형식이 COCO 다.** ultralytics 는 YOLO 형식(`cls cx cy w h`)을 읽는다. → 바꿔야 한다.
4. **카메라 표시가 없다.** 점수를 카메라별로 따로 내려면 그림마다 카메라를 붙여야 한다.

### 다른 컴퓨터에서 학습하기 (2026-11-18, `training/products/`)

학습은 다른 컴퓨터에서 돌리기로 했다 (사용자 결정). 그 컴퓨터에서 **한 폴더만 보고** 학습할 수 있게 `training/products/` 를 만들었다 — 안내문은 그 폴더의 `README.md`.

- 저장소에 올린 것: 라벨 1,194개 · 나눔별 목록 · `data.yaml`(경로를 안 적어 어느 컴퓨터에서나 읽힌다) · 그림 표 · 스크립트 3개(`prepare.py` 그림 가져다 놓기 · `check.py` 검사 · `train.py` 학습과 점수).
- 올리지 않은 것: **그림 1,194장** (얼굴). 사람이 따로 옮겨야 한다 — `outputs/products_rf/images/` 폴더나 같은 Roboflow 내보내기.
- 돌아오는 것: `handoff/<이름>/` 의 `best.pt` · `result.json`(검증 · 시험 점수, 전체 · 카메라별).
- 확인한 것: 이 컴퓨터(Windows · CPU)에서 그림 가져다 놓기 → 검사 → 아주 작은 학습(1바퀴 · 그림 5% · 해상도 320) → 점수 → `handoff/` 까지 한 번 돌렸다. **GPU 에서는 돌려 보지 못했다.** 다른 컴퓨터 · 다른 운영체제에서도 돌려 보지 못했다.
- Roboflow 폴더로 그림을 가져다 놓는 길은 파일 이름이 같아야 한다 — Roboflow 에서 새로 내보내면 이름(`rf.` 뒤 글자)이 달라져 짝을 못 찾을 수 있다 (같은 내보내기로만 확인했다).

### 학습 시간 (2026-11-17 잰 것 — 이 컴퓨터, CPU 8스레드 · GPU 없음)

- **모델을 키워도 손에 든 상품은 더 안 찾힌다** (시험 77 = 77, 같은 것을 놓친다). 놓치는 까닭은 모델 크기가 아니라 그런 모습의 그림 · 라벨이 모자란 쪽으로 보인다 — 단, 검증에서는 59 대 55 로 yolov8s 가 4개 더 찾았다. 수가 작아(66 · 99개) 어느 쪽이 맞는지 가르지 못한다.
- yolov8s 가 나은 것은 상자를 더 정확히 치는 것뿐이다 (시험 mAP50-95 0.756 대 0.746). 그 차이가 우리 판정(누가 무엇을 들었나)에 쓸모가 있는지는 모른다 — 판정에 끼워 본 적이 없다.
- 0.13초는 상품 탐지만이다. 사람 · 관절 모델 시간이 더해지고, 두 카메라를 다 돌리면 두 배다. 실시간 여부는 전체를 이어 돌려 재야 안다.
- 재는 동안 다른 프로그램(분석 도구 서버)이 떠 있었다. 오래 돌릴 때 느려지는지는 모른다.

- take · scan 장면에 실제로 손에 든 상품이 보이는지는 일부만 눈으로 봤다 (그림 2장 · 모아보기 19장 중 1장 = N01~N04). take 장면은 손이 레인에 닿거나 상품을 든 모습이 보였다. **scan 장면은 선반 카메라에서 손님 등이 보여 상품이 몸에 가린 것이 많았다** — 그런 장면은 선반 위 상품만 찍게 된다.
