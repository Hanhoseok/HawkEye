# 휴대폰 바코드 셀프 계산대 (학교 프로젝트 데모)

노트북은 **계산대 화면**, 휴대폰은 **바코드 리더기**가 되는 웹앱입니다.
앱 설치 없이 휴대폰 기본 카메라로 QR을 찍으면 스캔 페이지가 열리고, 상품 바코드를 찍으면 노트북 장바구니에 바로 반영됩니다.

- 서버: Node.js + Express, 저장소: SQLite(Node 내장 `node:sqlite`, 별도 설치 없음)
- 실시간 갱신: SSE(Server-Sent Events) — WebSocket보다 구현이 단순하고 재연결을 브라우저가 알아서 처리
- 바코드 인식: `html5-qrcode` (EAN-13, EAN-8, UPC-A/E, CODE-128, CODE-39 지원, 기기가 지원하면 브라우저 내장 BarcodeDetector 사용)
- 결제: **모의 결제**. 카드 정보 입력이나 청구 없이 품목·총액을 서버 주문 기록(SQLite `orders`)에 저장하고 "결제 완료" 화면을 보여줍니다. 결제 후에도 휴대폰 연결은 유지되어 다음 손님을 바로 스캔합니다.

## 1. 설치와 실행

요구 사항: Node.js **22.13 이상** (24 권장). `node -v`로 확인하세요.

```bash
npm install
```

```bash
npm start
```

실행하면 터미널에 접속 주소가 출력됩니다.

| 화면 | 주소 | 용도 |
|---|---|---|
| 계산대 (노트북) | http://localhost:3000/ | QR, 장바구니, 수량 수정, 테스트 결제 |
| 상품 등록 | http://localhost:3000/admin | 바코드·상품명·가격 등록/수정/삭제 |
| 샘플 바코드 | http://localhost:3000/samples | 실물 상품이 없을 때 화면의 바코드를 휴대폰으로 스캔 |
| 스캔 (휴대폰) | `<공개주소>/scan?s=<세션ID>` | QR을 찍으면 자동으로 열림 |

최초 실행 시 샘플 상품 6개가 자동 등록됩니다. 상품 데이터는 `data/shop.db`에 저장되어 서버를 재시작해도 남습니다.

테스트 실행:

```bash
npm test
```

## 2. 휴대폰 접속(HTTPS) 설정 — Cloudflare 빠른 터널

휴대폰 브라우저는 **HTTPS가 아니면 카메라를 열어주지 않습니다.** (localhost는 예외지만 휴대폰에서는 localhost가 노트북이 아닙니다.)
가장 간단한 방법은 Cloudflare의 빠른 터널(`cloudflared`)입니다. 계정 가입이 필요 없고 명령 한 줄로 HTTPS 공개 주소가 생깁니다.

1. `cloudflared` 설치 (한 번만)
   - Windows (PowerShell):
     ```bash
     winget install --id Cloudflare.cloudflared
     ```
     설치 후 PowerShell 창을 새로 여세요.
   - macOS: `brew install cloudflared`
2. 터미널 1에서 서버 실행:
   ```bash
   npm start
   ```
3. 터미널 2에서 터널 실행:
   ```bash
   cloudflared tunnel --url http://localhost:3000
   ```
   잠시 후 출력에 `https://xxxx-xxxx.trycloudflare.com` 형태의 주소가 나옵니다. (터널을 다시 켜면 주소가 바뀝니다.)
4. 노트북에서 http://localhost:3000/ 을 열고 QR 아래의 **"공개 접속 주소 설정"**을 펼친 뒤, 그 주소를 붙여넣고 **저장**을 누릅니다.
   QR이 즉시 다시 그려지고, 경고 문구(HTTP/localhost)가 사라져야 합니다. 설정은 DB에 저장되므로 서버를 재시작해도 유지됩니다.
   - 터미널에서 환경변수로 줄 수도 있습니다: PowerShell `$env:PUBLIC_URL="https://xxxx.trycloudflare.com"; npm start`
5. 휴대폰 기본 카메라 앱으로 노트북 화면의 QR을 찍어 링크를 엽니다. 주소가 `https://…trycloudflare.com/scan?s=…` 인지 확인하세요.
6. **스캔 시작**을 누르고 카메라 권한을 **허용**합니다.

> 터널 없이 같은 Wi-Fi의 `http://<노트북 IP>:3000` 으로도 접속은 되지만, HTTP라서 카메라는 막히고 **바코드 직접 입력**만 됩니다. 계산대 화면이 이 상태를 경고로 알려줍니다.
>
> 휴대폰에서 그 주소가 아예 안 열리면:
> - 노트북 IP가 맞는지 확인하세요. PowerShell에서 `ipconfig`를 쳐서 **Wi-Fi 어댑터**의 IPv4 주소를 쓰세요. WSL/Hyper-V의 `vEthernet` 주소(예: 172.30.176.1)나 169.254.x.x는 휴대폰에서 접속되지 않습니다. 서버는 Wi-Fi 주소를 우선 고르지만, 계산대 화면의 "공개 접속 주소 설정"에 직접 넣으면 확실합니다.
> - 휴대폰과 노트북이 **같은 Wi-Fi**여야 합니다. 학교·카페·통신사 공용 Wi-Fi는 기기 간 접속을 막는 경우가 많습니다. 이때는 휴대폰 핫스팟에 노트북을 연결하거나, 위의 터널을 쓰세요.
> - Windows 방화벽에서 Node.js 인바운드가 허용되어 있어야 합니다. 서버를 처음 실행할 때 뜨는 방화벽 창에서 "액세스 허용"을 눌러 주세요.
>
> 대안: 자체 서명 인증서를 `certs/key.pem`, `certs/cert.pem`에 두면 `https://<노트북 IP>:3443` 으로도 열립니다(휴대폰에서 인증서 경고를 수동으로 통과해야 함). 수업 시연에는 터널이 더 안정적입니다.

## 3. 시연 순서 (실제 상품으로)

### 준비: 내 상품 등록
1. 노트북에서 http://localhost:3000/admin 을 엽니다.
2. 실제 상품 포장 바코드 **아래에 인쇄된 숫자**(EAN-13은 13자리, 예: 8801234567890)를 바코드 번호에 입력하고, 상품명과 가격을 넣고 **추가**를 누릅니다.
   - 숫자 사이의 공백은 자동으로 제거됩니다. 12자리(UPC-A) 상품도 그대로 등록하면 됩니다.
3. 목록에서 **수정** / **삭제**로 고칠 수 있습니다. 서버를 껐다 켜도 남아 있는지 확인해 보세요.

### 시연
1. **QR 연결**: 노트북에서 http://localhost:3000/ 을 엽니다. 2절에서 공개 주소를 설정해 둔 상태여야 합니다. 휴대폰 카메라로 QR을 찍어 스캔 페이지를 엽니다. 휴대폰 상단 배지가 **연결됨**이면 성공입니다.
2. **스캔**: 휴대폰에서 **스캔 시작** → 카메라 허용 → 상품 바코드를 사각형 안에 맞춥니다.
   - 휴대폰에 `✔ 상품명 담김 (1개)` 토스트가 뜨고, 노트북 장바구니에 상품명·단가·수량·합계가 바로 나타납니다.
   - 한 상품은 **한 번만** 담깁니다. 같은 바코드를 다시 찍으면 휴대폰에 `이미 담긴 상품입니다` 가 뜨고 수량은 올라가지 않습니다. 수량은 노트북에서 바꿉니다.
   - 등록하지 않은 상품을 찍으면 휴대폰에 `미등록 상품입니다 (바코드)` 가 뜨고 장바구니는 바뀌지 않습니다.
   - 카메라가 안 되면 **바코드 직접 입력**에 숫자를 치고 **담기**를 누릅니다.
3. **수량 변경**: 노트북에서 `−` / `+` 또는 수량 칸에 숫자 입력, **삭제** 버튼. 휴대폰의 "현재 장바구니"도 함께 바뀝니다.
4. **테스트 결제**: 노트북에서 **테스트 결제**를 누르면 품목과 총액이 서버 주문 기록에 저장되고, 주문번호와 영수증이 있는 **결제 완료 (테스트)** 화면이 뜹니다. 장바구니는 비워지고, 아래 **최근 결제 내역**에 한 줄 추가됩니다.
5. **다음 손님**: 결제 화면의 **다음 손님**을 누르면 됩니다. 휴대폰에는 "결제 완료 ○○원 · 다음 손님 스캔 가능"이 잠깐 뜨고, **QR을 다시 찍지 않아도** 그대로 다음 손님 상품을 스캔할 수 있습니다. 결제할 때마다 주문이 하나씩 쌓입니다.
6. **비우기 / QR 재발급**: 결제 없이 장바구니를 비우려면 **비우기**, 다른 휴대폰으로 바꾸려면 QR 카드 아래 "휴대폰 연결 초기화"의 **QR 재발급**을 누릅니다. 재발급하면 이전 휴대폰 화면에 "연결 종료"가 뜨고 새 QR을 찍어야 합니다.

스캔 팁: 바코드가 화면 폭의 절반 이상 차지하게 15~25cm에서 비추고, 포장이 휘어 있으면 평평하게 펴 주세요. 샘플 바코드 페이지를 노트북 화면에 띄워 스캔할 때는 화면 밝기를 올리세요.

## 4. 확인 범위

**제가 직접 확인한 것** (노트북 브라우저와 자동 테스트)
- 서버 기동, 샘플 상품 자동 등록, 상품 등록/수정/삭제 API와 중복·유효성 검사
- 세션 생성, QR 생성, 공개 주소 설정이 QR 주소에 반영되는 것과 localhost/HTTP 경고
- 스캔 페이지에서 직접 입력으로 담기 → SSE로 노트북 장바구니 실시간 반영
- 같은 상품 재스캔 시 "이미 담김" 응답과 수량 유지, 미등록 바코드 거부(장바구니 변화 없음)
- 노트북에서 수량 +/−, 삭제, 테스트 결제 화면, 결제 시 주문 기록 저장과 장바구니 비움, 결제 후 같은 연결로 다시 담기
- 결제 없이 비우기, QR 재발급 시 새 QR 발급, 이전 세션 종료, 이전 휴대폰 화면에 종료 안내
- 중복 스캔 방지 로직(`public/js/dedupe.js`)의 단위 테스트
- 카메라가 없거나 권한이 거부됐을 때의 안내 문구

**휴대폰으로 직접 확인해야 하는 것** (제 환경에는 카메라와 휴대폰이 없습니다)
- 기본 카메라 앱으로 QR을 찍었을 때 스캔 페이지가 열리는지 (터널 주소 설정 후)
- **스캔 시작** 후 카메라 권한 허용과 실제 상품 EAN-13 인식 속도·정확도
- 같은 상품을 계속 비출 때 안내 토스트가 반복되지 않는지 (1.5초 기준은 `public/js/scan.js`의 `gapMs`로 조정 가능)
- 진동 피드백(지원 기기만), 가로/세로 화면에서의 레이아웃

## 5. 구조

```
server.js          Express 서버, 세션/장바구니(메모리), SSE, API
db.js              SQLite(상품, 설정, 주문 기록), 바코드 정규화, 샘플 상품
public/index.html  계산대(노트북)  + js/checkout.js
public/admin.html  상품 등록        + js/admin.js
public/scan.html   스캔(휴대폰)     + js/scan.js, js/dedupe.js
public/samples.html 등록 상품 바코드 이미지(JsBarcode)
test/              node:test 기반 API/중복방지 테스트
data/shop.db       SQLite 파일 (자동 생성)
```

주요 API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/sessions/current | 현재 계산대 세션(없으면 생성) |
| POST | /api/sessions | QR 재발급(이전 세션 종료, 연결된 휴대폰 끊김) |
| POST | /api/sessions/:id/clear | 결제 없이 장바구니 비우기 |
| GET | /api/orders?limit=20 | 최근 결제(주문) 기록: 품목, 수량, 총액, 시각 |
| GET | /api/sessions/:id/qr | QR 이미지(data URL)와 스캔 주소 |
| GET | /api/sessions/:id/events | SSE 스트림 (`cart`, `paid`, `closed`) |
| POST | /api/sessions/:id/scan | `{barcode}` 담기. 이미 담긴 상품이면 `duplicate: true`로 응답하고 수량 유지 (404 미등록, 410 종료, 409 결제됨) |
| PATCH/DELETE | /api/sessions/:id/items/:barcode | 수량 변경 / 삭제 |
| POST | /api/sessions/:id/checkout | 모의 결제: 주문 기록 저장 후 장바구니 비움, 세션 유지 |
| GET/POST/PUT/DELETE | /api/products | 상품 CRUD |
| GET/PUT | /api/settings/public-url | QR에 쓸 공개 주소 |

환경변수: `PORT`(기본 3000), `PUBLIC_URL`, `DB_PATH`, `HTTPS_PORT`(기본 3443, certs/ 있을 때만)
